한줄 요약

유압 굴착기의 실시간 궤적 계획을 위해 global planner (trajectory optimization)와 local planner (MPC + disturbance estimation)를 통합한 프레임워크를 제안하며, force/torque, power, cylinder displacement, flow rate 등 물리적 제약조건을 모두 만족하면서 30 Hz 이상의 실시간 궤적 재계획이 가능함을 시뮬레이션으로 검증하였다.

1. 연구 배경

1.1 문제 정의

  • 유압 굴착기(hydraulic excavator)의 굴착 작업 자동화에는 다양한 operational constraints (굴착량, 버킷 자세 등)와 physical constraints (force/torque 한계, 펌프 유량 한계, 파워 한계 등)를 동시에 만족하는 궤적 계획이 필요
  • 기존 trajectory optimization 방법은 전체 궤적을 한 번에 offline으로 최적화하므로, 운영 중 발생하는 외란(disturbance) — 토양-버킷 상호작용, 유압 실린더 마찰 — 에 취약
  • 외란으로 인해 최적성 저하는 물론 제약조건 위반(constraint violation)까지 발생 가능

1.2 기존 연구 분류

분류 대표 연구 특징 한계
Trajectory optimization [6,7,9] 비용함수+제약조건+시스템 동역학 기반 전체 궤적 최적화 Offline 계산, 외란 미대응, 단순 커널 파라미터화
Receding horizon / MPC [12,13] 이동 수평선 방식 궤적 최적화 [12] 단일 입력 decoupled 동역학만 고려, [13] 연산시간 부족 (~3.3 Hz)
Non-optimization 기반 [1,14-16] DMP, reachability map, 계층적 제어 제약조건 명시적 고려 불가, feasibility 보장 어려움

1.3 연구 기여 (Contributions)

  1. Global + Local planner 통합: operational constraints와 physical constraints를 모두 고려
  2. 축소 차원 global trajectory optimization: 수 초 이내 계산 가능한 문제 정식화
  3. 실시간 제약 궤적 생성: 외란 추정 기반 disturbance-aware 실시간 궤적 계획

2.2 굴착기 구성 (Hyundai HX300L)

🔧 APEX 구현 대조 — 플랫폼

  • 논문은 30톤급 현대 HX300L, 우리는 8.5톤급 E85 (AGX 물리 시뮬레이터).
  • 같은 4개 부위 구성입니다: 몸통 회전(cabin) / 붐 / 암 / 버킷. 링크 길이·기준 자세·관절 한계 수치는 apex_e85_params.py 파일 하나에 모아 두고 모든 코드가 이 파일만 참조합니다 (수치가 두 곳에서 어긋나는 사고 방지).
  • 체급 차이의 의미: 8.5톤 장비가 팔을 4.4m 뻗으면 내리누를 수 있는 힘이 ~20kN뿐이라, 한 번에 깊이 팔 수 없습니다. 우리가 한 pass에 25~44cm씩 여러 번 나눠 파는 것은 결함이 아니라 체급에 맞는 정상 동작입니다.

3. 핵심 기술

3.1 운동학 (Kinematics)

Configuration을 관절 각도 또는 실린더 변위로 표현:

\mathbf{q}_\theta = [\psi_U \; \theta_B \; \theta_A \; \theta_K]^\top \in \mathbb{R}^4, \quad \mathbf{q}_L = [\psi_U \; L_B \; L_A \; L_K]^\top \in \mathbb{R}^4

두 표현 사이의 비선형 전단사(bijective) 매핑:

\mathbf{q}_\theta = g_L(\mathbf{q}_L), \quad \mathbf{q}_L = g_\theta(\mathbf{q}_\theta), \quad \dot{\mathbf{q}}_\theta = J_L(\mathbf{q}_L)\dot{\mathbf{q}}_L, \quad \dot{\mathbf{q}}_L = J_\theta(\mathbf{q}_\theta)\dot{\mathbf{q}}_\theta \tag{1}

버킷 팁 자세 (bucket tip pose):

\mathbf{E} = [E_x(\mathbf{L}) \; E_z(\mathbf{L}) \; \theta(\mathbf{L})]^\top \in \mathbb{R}^3

여기서 L = [LB LA LK]⊤, θ = θB + θA + θK.

🔧 APEX 구현 대조 — 식(1) — 각도↔실린더 변환을 실측 표로

대응: 식(1)의 “관절 각도 ↔ 실린더 길이” 변환입니다. 우리는 시뮬레이터에서 팔을 전 구간 움직여 보며 실측한 대응표(조견표)를 만들어 씁니다 (e85_theta_agx_calibration.json).

핵심 발견 (2026-08-13): 버킷은 링크 4개가 사다리꼴로 얽힌 구조라 각도와 실린더 길이가 비례 관계가 아닙니다 (열리는 쪽과 오므리는 쪽의 기울기가 2배 차이). 처음엔 1차식(비례+상수)으로 근사했다가 오차가 커서 폐기하고, 40칸 실측 표에서 값을 찾아 쓰는 방식으로 바꿨습니다: 

# apex_e85_params.py — 버킷 각도 → 실린더 좌표 (실측 40칸 표에서 보간)
def bucket_agx_from_urdf(u_k, calibration):
    lk = calibration["bucket"].get("lookup_table")
    if lk and lk.get("map") == "piecewise_linear" and lk.get("monotone"):
        return np.interp(u_k, lk["urdf"], lk["agx"])   # 표에서 찾아 보간
  • 표 방식의 오차: 평균 0.0005 라디안 (1차식은 최대 0.1 — 200배 차이). 왕복 변환 오차 0
  • 버킷 이빨 끝 위치 계산(FK)은 시뮬레이터가 알려주는 실제 이빨 위치와 대조해 검증
  • 판정 🟢 충실 — 논문의 “비선형 일대일 매핑”을 실측으로 구현

3.2 동역학 (Dynamics)

관절 각도 기반 동역학 (Euler-Lagrange):

\dot{\mathbf{x}}_\theta = \begin{bmatrix} \dot{\mathbf{q}}_\theta \\ \ddot{\mathbf{q}}_\theta \end{bmatrix} = \begin{bmatrix} \dot{\mathbf{q}}_\theta \\ M_\theta^{-1}(-\mathbf{h}_\theta + J_\theta^\top \mathbf{u} + \boldsymbol{\Delta}) \end{bmatrix} =: f_\theta(\mathbf{x}_\theta, \mathbf{u}, \boldsymbol{\Delta}) \tag{2}
기호 의미
xθ = [qθ⊤ q̇θ⊤]⊤ ∈ ℝ8 시스템 상태
u = [TU FB FA FK]⊤ ∈ ℝ4 제어 입력 (swing torque + 유압 실린더 force)
Mθ(qθ) ∈ ℝ4×4 질량 행렬
hθ(qθ, q̇θ) ∈ ℝ4 Coriolis-원심력 + 중력 합성항
Δ ∈ ℝ4 총괄 외란 (lumped disturbance)

수식 상세 전개

Mθ와 hθ의 원소별 전개, 변수 색깔 구분(측정/CAD/미지), FL과의 연결은 별도 노트 참조: 02_research/필드로봇/굴착기 동역학 M과 h 수식 해부 — 굴착기 동역학 M과 h 수식 해부

실린더 변위 기반 동역학 (local planning에서 사용):

\dot{\mathbf{x}}_L = \begin{bmatrix} \dot{\mathbf{q}}_L \\ \ddot{\mathbf{q}}_L \end{bmatrix} = \begin{bmatrix} \dot{\mathbf{q}}_L \\ M_L^{-1}(-\mathbf{h}_L + \mathbf{u} + \boldsymbol{\Delta}_L) \end{bmatrix} =: f_L(\mathbf{x}_L, \mathbf{u}, \boldsymbol{\Delta}_L) \tag{3}

여기서 ML(qL) = JL⊤ M̃L JL, hL = JL⊤(M̃L J̇L q̇L + h̃L), ΔL = JL⊤Δ.

🔧 APEX 구현 대조 — 식(2)(3) — 무게·관성 모델: 구조는 가동, 수치는 미보정

대응: 식(2)의 M(팔이 얼마나 무거운가)과 h(중력·회전 관성 힘)를 계산하는 코드가 dynamics.py에 있고, 실제로 3군데서 사용 중입니다:

  1. 국소 제어 최적화의 “지금 자세에서 중력이 이만큼 당긴다” 항
  2. “이 움직임에 힘이 얼마나 드는가” 계산 (한계 초과 판정용)
  3. 흙 저항 추정기의 “저항이 없다면 이렇게 움직였을 것” 예측

숨기지 않는 한계: 이 모델의 수치(무게·관성·힘 한계)는 실측 보정을 하지 않은 임시값입니다. 시뮬레이터가 알려주는 실제 실린더 힘과 모델 예측을 비교하면 상관이 약합니다 (상관계수 0.07~0.43 수준; 암 축은 부호가 반대로 나와 지렛대 방향 해석 오류 후보로 기록). 그래서 “힘 한계 몇 % 사용” 같은 판정은 판정 불가로 못박고, 합격 판정은 굴착 결과(깊이·부피)로 합니다.

판정 🟡 부분 — 구조는 연결·가동, 수치 보정은 유압 시뮬 과제와 함께 후속

3.3 Global Planning

굴착 작업은 3개 phase로 구성:

Phase 1 초기 위치 → 지표면 진입
Bernstein 파라미터화
Phase 2 토양 굴착
Waypoint 최적화
Phase 3 토양 운반
Bernstein 파라미터화

Phase 2: 굴착 궤적 최적화

n2 + 1개 waypoint L0, L1, ⋯, Ln₂로 이산화하고, 비용함수를 다음과 같이 정의:

J_{\text{Phase2}} = w_d \sum_{k=1}^{n_2} \|\mathbf{L}_k - \mathbf{L}_{k-1}\|_W^2 - w_v V \tag{4}
항 의미
wd Σ ‖Lk − Lk−1‖W2 유압 실린더 이동 거리 최소화 (에너지 비용)
wvV 굴착 체적 최대화

지표면과 목표 형상은 다항식으로 모델링:

z_{\text{surf}} = a_0^{\text{surf}} + a_1^{\text{surf}}x + \cdots + a_{n_{\text{surf}}}^{\text{surf}} x^{n_{\text{surf}}} \tag{5}
z_{\text{target}} = a_0^{\text{target}} + a_1^{\text{target}}x + \cdots + a_{n_{\text{target}}}^{\text{target}} x^{n_{\text{target}}}

굴착 체적 (swept volume, 사다리꼴 적분):

V_{\text{swept}} = \int_{x_{n_2}}^{x_0} z_{\text{surf}}(x)\,dx - \frac{z_0 + 2z_1 + \cdots + 2z_{n_2-1} + z_{n_2}}{2n_2} \cdot (x_0 - x_{n_2}) \tag{6}
V = \min\{V_{\text{swept}},\; V_{\text{cap}}(\theta(\mathbf{L}_{n_2}))\}

Phase 2 제약조건 요약:

Phases 1 & 3: Bernstein 다항식 파라미터화

Bernstein 다항식:

p(s) = \sum_{k=0}^{n} \beta_k \binom{n}{k} s^k (1-s)^{n-k}, \quad s \in [0,1] \tag{7}

Phases 1, 3의 최적화 문제:

\min_{\beta_k, T} \int_0^T \frac{1}{2} \mathbf{u}^\top W_u \mathbf{u}\, dt \tag{8}
\text{s.t.}\quad \mathbf{q}_L^l \leq \beta_k \leq \mathbf{q}_L^u, \quad \dot{\mathbf{q}}_L^l \leq \frac{n \cdot (\beta_{k+1} - \beta_k)}{T} \leq \dot{\mathbf{q}}_L^u

Phase 3 추가 제약 (토양 흘림 방지):

\theta_0 \leq \theta(\beta_k) \leq \pi \tag{9}

🔧 APEX 구현 대조 — 식(7)(8)(9) — 진입·인양 경로: 모양은 충실, 시간 배분은 단순화

대응: 식(7)의 Bernstein 곡선(제어점 몇 개로 부드러운 곡선을 만드는 방법)은 _bernstein 함수에 그대로 있습니다: 

def _bernstein(control_points, samples):
    for i in range(degree + 1):
        coeff = comb(degree, i) * (t**i) * ((1.0 - t)**(degree - i))
        curve += coeff[:, None] * points[i]

단순화한 부분 (🟡): 논문은 식(8)로 “힘이 가장 적게 드는 시간 배분”까지 최적화하지만, 우리는 곡선 모양은 고정하고 속도 상한(구간별 팁 속도 0.5/0.25/0.5 m/s)에 맞춰 시간만 재배분합니다.

식(9) 흘림 방지 (🟢, 방식만 다름): 논문은 부등식 제약, 우리는 들어올리는 동안 오므림 각도를 직접 유지시키고 + 운반 높이를 강제 조건으로 겁니다.

운전자(사용자) 관찰로 고친 것 2건: ① 내려갈 때 버킷을 활짝 벌린 자세로 (오므린 채 내려가면 등판이 먼저 땅에 닿는 비정상 동작) ② 쏟을 때 각도 1.30rad를 명령해도 실제로는 8%밖에 안 열리던 결함 (위 3.1의 비비례 관계 탓) → 실측 가동범위의 92%를 직접 목표로 바꾸고 2초간 유지.

3.4 Local Planning (MPC)

물리적 제약조건

\mathbf{u}^l \leq \mathbf{u} \leq \mathbf{u}^u \tag{10a}
p = \mathbf{u}^\top \dot{\mathbf{q}}_L \leq p^u \tag{10b}
\mathbf{L}^l \leq \mathbf{L} \leq \mathbf{L}^u \tag{10c}
f_i = A_i(\operatorname{sgn}(\dot{\mathbf{q}}_L))^\top \dot{\mathbf{q}}_L^{\text{abs}} \leq f_i^u, \quad i = 1,2 \tag{10d}
제약 물리적 의미
(10a) Force/torque limit 각 액추에이터의 힘/토크 상하한
(10b) Power limit 유압 펌프의 총 파워 상한 (모든 액추에이터가 동일 파워원 공유)
(10c) Cylinder displacement 실린더 변위의 물리적 상하한
(10d) Pump flow rate 2개 유압 펌프의 유량 제한

🔧 APEX 구현 대조 — 식(10a-d) — 4가지 한계 조건이 코드에 1:1로

대응: 국소 제어가 매번 푸는 최적화 문제에 논문의 4가지 한계가 그대로 들어 있습니다 (local_mpc.py): 

approx_u  = inertia*v + damping*qd + h0    # (10a) 이 움직임에 필요한 힘 ≤ 한계의 90%
power     = approx_u * qd                   # (10b) 파워(힘×속도) ≤ 한계
q_L       = neutral + scale*q              # (10c) 실린더가 물리적 이동 범위 안
pump_flow = Σ|q̇_L|                         # (10d) 유량(실린더 속도 합) ≤ 펌프 용량

논문과 다른 점: (10b) 파워를 논문은 전체 합으로 한 번에, 우리는 축마다 따로 제한. (10d) 유량도 논문은 펌프 2대에 나눠 배분, 우리는 한 덩어리로 합산 (🟡 단순화).

판정의 정직성: 한계 초과 여부는 잘라내기 전의 원래 힘 값으로 판정합니다 (먼저 잘라놓고 “한계 안 넘었네”라고 하면 눈속임이므로).

“이 조건들이 진짜 일하는가” 검증: 제약을 끄고 단순 추종만 시켜보면 858번 중 645~657번 한계 초과 발생 — 즉 제약이 76% 구간에서 실제로 개입하고 있었습니다. 단, 제약을 켜도 “필요 힘이 한계를 넘는다”는 경고 표시는 ~24% 남는데, 이는 위 3.2의 미보정 힘 한계 수치 탓입니다 (기록된 한계).

외란 추정 (Disturbance Estimation)

모멘텀 기반 외란 추정 (momentum-based disturbance estimation):

\hat{\boldsymbol{\Delta}} = K_E \left( \mathbf{p} - \mathbf{p}(0) - \int_0^t \left( J_\theta^\top \mathbf{u} + C_\theta^\top \dot{\mathbf{q}}_\theta - G_\theta + \hat{\boldsymbol{\Delta}} \right)d\tau \right), \quad \mathbf{p} = M_\theta \dot{\mathbf{q}}_\theta \tag{11}

Ṁθ = Cθ + Cθ⊤ 성질을 활용하면, 실제 외란 Δ의 저역통과 필터(low-pass filter)로 작동:

\dot{\hat{\boldsymbol{\Delta}}} = K_E(\boldsymbol{\Delta} - \hat{\boldsymbol{\Delta}})

실린더 변위 기반 추정값: Δ̂L = JL⊤Δ̂ = [Δ̂U Δ̂B Δ̂A Δ̂K]⊤

🔧 APEX 구현 대조 — 식(11) — 흙 저항 실시간 추정: 구현 + 효과 입증

대응: disturbance.py — “모델대로면 이렇게 움직였어야 하는데 실제는 이만큼 못 움직였다 → 그 차이가 흙의 저항”이라는 논문 식(11)의 아이디어를, 잡음을 걸러내는 필터와 함께 구현: 

predicted = 모델이 예측한 가속도(저항 0 가정)
residual_torque = M @ (실측 가속도 - predicted)   # = 흙 저항 추정
estimate = 0.8*직전_추정 + 0.2*residual_torque    # 저역통과(잡음 제거)
  • 효과 입증 (핵심 성과): 이 추정기를 끄면 같은 궤적인데 7.2cm 얕게 파고 흙은 45% 덜 담깁니다 (3회 반복 중앙값, 서로 다른 3가지 측정이 일치). 즉 흙을 뚫고 들어가는 능력이 이 부품에서 나옵니다.
  • 주의할 점 (정직 기록): ① 우리 모터는 속도 명령형이라, 추정값에는 흙 저항 외에 “모터 반응 지연”도 섞입니다. ② 추정값이 안전 상한(힘 한계의 80%)에 거의 항상 붙어 있어, 흙이 4배 단단해져도 추정값 숫자는 안 변합니다 — 미보정 힘 수치 탓이며 개선 항목 (🟡).

MPC 문제 정식화

원래 비선형 MPC:

\min_{\mathbf{u}_k} \|\mathbf{x}_N - \mathbf{x}_{r,N}\|_P^2 + \sum_{k=0}^{N-1} \left( \|\mathbf{x}_k - \mathbf{x}_{r,k}\|_Q^2 + \|\mathbf{u}_k\|_R^2 \right) \tag{12}
\text{s.t.}\quad \mathbf{x}_{k+1} = f_d(\mathbf{x}_k,\mathbf{u}_k,\hat{\boldsymbol{\Delta}}_k), \quad c_{k,i}(\mathbf{x}_k,\mathbf{u}_k) \geq 0

Feedback Linearization 기반 단순화

가상 입력 v ∈ ℝ4와 피드백 선형화 제어 법칙 도입:

\mathbf{u} = \operatorname{FL}(\mathbf{x},\mathbf{v}) := \mathbf{h}_L + M_L\mathbf{v} - \hat{\boldsymbol{\Delta}}_L

이를 통해 비선형 동역학을 선형 동역학으로 변환:

\dot{\mathbf{x}} = A_c\mathbf{x} + B_c\mathbf{v}, \quad A_c = \begin{bmatrix} 0_{4\times4} & I_4 \\ 0_{4\times4} & 0_{4\times4} \end{bmatrix}, \quad B_c = \begin{bmatrix} 0_{4\times4} \\ I_4 \end{bmatrix} \tag{13}

최종 MPC 문제 (선형화된 동역학 기반):

\min_{\mathbf{v}_k} \|\mathbf{x}_N - \mathbf{x}_{r,N}\|_{\tilde{P}}^2 + \sum_{k=0}^{N-1} \left( \|\mathbf{x}_k - \mathbf{x}_{r,k}\|_{\tilde{Q}}^2 + \|\mathbf{v}_k\|_{\tilde{R}}^2 \right) \tag{14}
\text{s.t.}\quad \mathbf{x}_{k+1} = A_d\mathbf{x}_k + B_d\mathbf{v}_k, \quad c_{k,i} \left( \mathbf{x}_k, \operatorname{FL}(\mathbf{x}_k,\mathbf{v}_k) \right) \geq 0
비선형 동역학 (3) fL(xL, u, ΔL)
→
선형 동역학 (13) Feedback Linearization
u = hL + MLv − Δ̂L
→
이산 선형 동역학 xk+1 = Adxk + Bdvk
→
MPC 문제 (14) 선형 동역학 · 물리 제약 유지 · DDP + Augmented Lagrangian

외란 추정 (11): 모멘텀 기반 · 저역통과 필터 특성 → MPC 문제에 입력

🔧 APEX 구현 대조 — 식(12)(13)(14) — 제어 계산 구조: 대응 + 속도모터용 적응

용어: FL(feedback linearization, 피드백 선형화) = “팔 무게·중력·흙 저항을 미리 계산해 상쇄하는 힘을 더해주면, 복잡한 기계가 단순한 수식처럼 움직인다”는 제어 기법. 이때 계산되는 힘을 이 문서에서 “보정 힘(FL 토크)”이라 부릅니다.

식(12)→(14) 최적화: 논문은 앞으로 1초간의 입력 열 전체를 고급 솔버(DDP)로 풀고, 우리는 “지금 이 순간의 가속도 하나”만 정하는 단순화 버전을 범용 솔버(IPOPT)로 풉니다 (🟡): 

# 목표와의 거리(위치·속도)를 줄이는 가속도 v를, 위 4가지 한계 안에서 선택
objective += 120*(위치오차²) + 18*(속도오차²)

식(14) 보정 힘: 논문 수식 u = h + M·v − Δ̂ 그대로 구현 (+마찰 항):

raw_u = M@가속도 + 중력항 + 마찰*속도 - 흙저항추정

우리 플랜트 적응 (중요한 차이): 이 보정 힘은 속도 모터에 직접 넣을 수 없으므로, 속도 명령을 그만큼 더 세게 미는 방식으로 같은 효과를 냅니다: 목표속도 = 현재속도 + (v − M⁻¹·흙저항추정)·dt.

꺼보기 검증의 정직한 결과: 흙 저항 부분을 끄면 성능이 크게 나빠지지만(위 식(11) 주석), 중력·관성 보정 부분만 끄면 결과가 안 변했습니다 (우리 굴착이 힘 한계에 안 걸릴 만큼 온화해서 이 보정이 개입할 기회가 없음). “이 부품의 단독 효과는 이 조건에서 증명 안 됨”으로 기록.

계산 속도: 우리 단순화 덕에 100번 중 95번이 7ms 이내 (논문 21.7~30.2ms). 단 가끔 23~25ms 튀는 이봉 분포.

덜컹거림과의 연결 (2026-08-14 사용자 관찰): “가속도 하나만 정해 유지”하는 우리 단순화는 가속도가 계단식으로 바뀌어 몸체가 꿀렁이는 구조적 원인 후보 1순위입니다. 논문처럼 입력 열을 부드럽게 최적화하면 완화 여지. 접촉 중 14~20% 스텝에서 백업 제어로 전환되며 명령이 살짝 튀는 것도 원인 후보. → 다음 개선 작업으로 등록됨.

조건 다양성 얕은/깊은 2가지 5가지 (단단한 흙/모래/경사/둔덕/조합) + 라이브 재현

굴착량은 기존 자동굴착(scripted) 대비 84% — 한계 조건을 지키는 대가로 기록.

5. 한계 및 향후 연구

  • 시뮬레이션만 검증: 실제 굴착기에서의 실험 검증이 수행되지 않음
  • 환경 사전 지식 가정: 지면 형상(ground shape)을 사전에 알고 있다고 가정 (LiDAR, 카메라 등으로 취득 가능하나 불확실성 미고려)
  • 토양 모델의 단순화: Modified FEE 기반 토양-버킷 상호작용 모델은 시뮬레이션용이며, 실제 토양 조건의 다양성 미반영
  • 단일 굴착 작업만 고려: 연속적인 반복 굴착, 트럭 적재 등 상위 수준 태스크 플래닝 미포함
  • 향후 연구: 실제 굴착기에서의 알고리즘 검증 (논문 결론에서 명시)

논문의 한계 우리 상태
시뮬레이션만 검증 같음 (실차 이식은 별도 로드맵)
지면 모양을 미리 안다고 가정 해소 — LiDAR 스캔→자동 수식화 (경사·둔덕 실측 검증)
흙 모델 단순화 부분 해소 — 입자 물리(AGX) + 물성 3종 바꿔 검증 (단 3개 수치만 변경)
한 번의 굴착만 다룸 부분 해소 — 3-pass 연속 + 회전 덤프 (그 위의 작업 계획은 미포함)

우리에게만 있는 한계 (논문에는 없는 것): ① 무게·관성·힘 한계 수치 미보정 ② 힘으로 미는 모터 없음(속도 모터 — 보정 힘은 속도로 환산 적용) ③ 중력·관성 보정 부품의 단독 효과 미증명 ④ pass 단위 재계획 ⑤ 덜컹거림(저크) — 다음 개선 작업.

한마디로 정리

  • Global + Local planner 통합 프레임워크로 유압 굴착기의 실시간 궤적 계획 구현
  • Force/torque, power, cylinder displacement, flow rate 등 4가지 물리적 제약조건 동시 충족 달성
  • Feedback linearization으로 비선형 MPC를 선형화하여 30 Hz 이상 실시간 연산 달성
  • 모멘텀 기반 외란 추정으로 마찰 및 토양 상호작용 disturbance-aware planning 구현
  • Shallow/deep excavation 두 시나리오에서 제약 만족 + 전역 궤적 추종 검증 완료
  • 실제 굴착기 실험 미수행 — 시뮬레이션만 검증
