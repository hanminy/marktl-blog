📖 용어 미니 사전 (주석에 나오는 말들)
  • 전역 계획 / 국소 제어: 전역 = 굴착 한 번 전체의 궤적을 미리 계산 (수 초, 굴착 1회당 1번). 국소 = 실행 중 반복해서 다음 순간의 움직임을 결정 (논문 33~46Hz, 우리 20Hz)
  • MPC: 앞으로 조금 뒤까지 내다보며 “한계를 안 넘는 최선의 움직임”을 매번 다시 계산하는 제어 방식
  • FL (피드백 선형화): 팔 무게·중력·흙 저항을 미리 계산해 상쇄해 주는 기법. 여기서 계산되는 힘 = “보정 힘(FL 토크)”
  • 최적화 솔버 (IPOPT/CasADi, DDP): “조건을 지키며 점수를 최대화하는 답”을 찾아 주는 수치 라이브러리. 논문은 DDP, 우리는 IPOPT 사용
  • PD 제어 / 백업 제어: 오차에 비례해 미는 가장 단순한 제어. 최적화가 실패한 순간에만 임시로 대신 씀
  • d̂ (흙 저항 추정값): 관측기가 실시간 추정한 “흙이 버킷을 미는 힘”
  • raw_u (원시 힘 값): 안전 한계로 잘라내기 전의, 계산된 그대로의 필요 힘 — 한계 초과 판정은 이 값으로 해야 정직함
  • p95: 100번 중 95번은 이 값 이하라는 뜻 (최악값에 가까운 대표치)
  • 미보정(UNCALIBRATED): 실측으로 맞추지 않은 임시 수치 — 이 수치에 기반한 판정은 “판정 불가”로 기록
  • pass: 굴착 한 번(진입→긁기→들기→쏟기)의 단위. 3-pass = 같은 자리를 세 번 점점 깊게 팜

한줄 요약

유압 굴착기의 실시간 궤적 계획을 위해 global planner (trajectory optimization)와 local planner (MPC + disturbance estimation)를 통합한 프레임워크를 제안하며, force/torque, power, cylinder displacement, flow rate 등 물리적 제약조건을 모두 만족하면서 30 Hz 이상의 실시간 국소 궤적 재계획이 가능함을 시뮬레이션으로 검증하였다. 전역 궤적은 굴착 1회당 1번 계산되는 고정 기준값이다.

1. 연구 배경

1.1 문제 정의

  • 유압 굴착기(hydraulic excavator)의 굴착 작업 자동화에는 다양한 operational constraints (굴착량, 버킷 자세 등)와 physical constraints (force/torque 한계, 펌프 유량 한계, 파워 한계 등)를 동시에 만족하는 궤적 계획이 필요
  • 기존 trajectory optimization 방법은 전체 궤적을 한 번에 offline으로 최적화하므로, 운영 중 발생하는 외란(disturbance) — 토양-버킷 상호작용, 유압 실린더 마찰 — 에 취약
  • 외란으로 인해 최적성 저하는 물론 제약조건 위반(constraint violation)까지 발생 가능

1.2 기존 연구 분류

분류 대표 연구 특징 한계
Trajectory optimization [6,7,9] 비용함수+제약조건+시스템 동역학 기반 전체 궤적 최적화 Offline 계산, 외란 미대응, 단순 커널 파라미터화
Receding horizon / MPC [12,13] 이동 수평선 방식 궤적 최적화 [12] 단일 입력 decoupled 동역학만 고려, [13] 연산시간 부족 (~3.3 Hz)
Non-optimization 기반 [1,14-16] DMP, reachability map, 계층적 제어 제약조건 명시적 고려 불가, feasibility 보장 어려움

1.3 연구 기여 (Contributions)

  1. Global + Local planner 통합: operational constraints와 physical constraints를 모두 고려
  2. 축소 차원 global trajectory optimization: 수 초 이내 계산 가능한 문제 정식화
  3. 실시간 제약 궤적 생성: 외란 추정 기반 disturbance-aware 실시간 궤적 계획

논문과 대조할 점 2가지 (미리 알고 보시면 좋은 것):

  1. 논문은 계산한 힘(토크)을 장비에 인가합니다 — 정확히는 MPC가 가상 입력 v를 내고, FL이 u = hL + MLv − Δ̂L로 환산한 뒤 PID 피드백이 더해져 인가됩니다(순수 피드포워드가 아님). 우리 시뮬레이터 모터는 속도 명령만 받기 때문에, 힘 계산은 “한계를 넘는지 판정”하는 데 쓰고 실제 명령은 속도로 보냅니다.
    • 단, 논문도 스풀 변위 → 유량 → 압력 → 힘으로 이어지는 밸브 동역학은 생략하고 힘을 바로 넣는 시뮬레이션입니다. 유압 계층은 (10b) 파워·(10d) 유량 용량 제약으로만 반영합니다. 실차에서는 논문 역시 이 계층을 밸브 제어로 다시 풀어야 합니다. 즉 우리의 속도 명령 제약은 “논문보다 못한 것”이라기보다 같은 문제를 다른 층위에서 만난 것에 가깝습니다. 힘으로 직접 미는 유압 시뮬은 후속 과제입니다.
  2. 논문이 실시간으로 다시 계획하는 것은 국소 MPC뿐입니다(1초 horizon을 20ms 주기로, 33~46Hz). 전역 계획은 논문도 굴착 1회당 1번이고 계산에 1.6~2.1초가 걸려 루프 안에서 돌 수 없습니다. 전역 궤적 xr은 MPC의 고정 기준값이며, 물리적 한계를 초과해도 그대로 둡니다(§4.2). 우리도 동일하게 pass 단위로 전역 계획을 세우되, pass 사이에 LiDAR로 지형을 다시 스캔합니다 — 논문의 “지면을 미리 안다” 가정을 그만큼 덜어낸 쪽입니다.

3. 핵심 기술

3.1 운동학 (Kinematics)

Configuration을 관절 각도 또는 실린더 변위로 표현:

qθ = [ψU θB θA θK]T ∈ ℝ4, qL = [ψU LB LA LK]T ∈ ℝ4

두 표현 사이의 비선형 전단사(bijective) 매핑:

qθ = gL(qL), qL = gθ(qθ), q̇θ = JL(qL)q̇L, q̇L = Jθ(qθ)q̇θ (1)

버킷 팁 자세(bucket tip pose):

E = [Ex(L) Ez(L) θ(L)]T ∈ ℝ3

여기서 L = [LB LA LK]T, θ = θB + θA + θK.

🔧 APEX 구현 대조 — 식(1) — 각도↔실린더 변환을 실측 표로

대응: 식(1)의 “관절 각도 ↔ 실린더 길이” 변환입니다. 우리는 시뮬레이터에서 팔을 전 구간 움직여 보며 실측한 대응표(조견표)를 만들어 씁니다(e85_theta_agx_calibration.json).

핵심 발견 (2026-08-13): 버킷은 링크 4개가 사다리꼴로 얽힌 구조라 각도와 실린더 길이가 비례 관계가 아닙니다(열리는 쪽과 오므리는 쪽의 기울기가 2배 차이). 처음엔 1차식(비례+상수)으로 근사했다가 오차가 커서 폐기하고, 40칸 실측 표에서 값을 찾아 쓰는 방식으로 바꿨습니다:

# apex_e85_params.py — 버킷 각도 → 실린더 좌표 (실측 40칸 표에서 보간)
def bucket_agx_from_urdf(u_k, calibration):
    lk = calibration["bucket"].get("lookup_table")
    if lk and lk.get("map") == "piecewise_linear" and lk.get("monotone"):
        return np.interp(u_k, lk["urdf"], lk["agx"])   # 표에서 찾아 보간
  • 표 방식의 오차: 평균 0.0005 라디안 (1차식은 최대 0.1 — 200배 차이). 왕복 변환 오차 0
  • 버킷 이빨 끝 위치 계산(FK)은 시뮬레이터가 알려주는 실제 이빨 위치와 대조해 검증
  • 판정 🟢 충실 — 논문의 “비선형 일대일 매핑”을 실측으로 구현
보강 (2026-08-14)

🟢 판정은 위치 매핑에 한해 유효하다. 원문 각주 1은 “This is true within a physically feasible region, and the region is considered in the local planning as a cylinder displacement constraint” — 전단사성의 유효 범위를 (10c)로 처리한다는 뜻이다. 우리 쪽에서 이 각주에 대응하는 것은 monotone 체크가 아니라 §3.4의 q_L = neutral + scale*q 쪽이다(monotone은 np.interp의 전제조건 검사에 가깝다). 주의할 점은 np.interp가 정의역 밖에서 에러 없이 끝값으로 클램프한다는 것 — 범위 이탈이 조용히 틀린 값으로 흡수되므로, (10c)가 실제로 먼저 걸리는지는 별도 확인이 필요하다.

미해결 (2026-08-14)

이 표에서 야코비안 JL을 뽑아 쓰는지가 기록되어 있지 않다. piecewise_linear 보간의 미분은 구간별 상수 계단 함수이므로, 만약 여기서 JL·J̇L을 유도한다면 J̇L이 구간 내부에서 0이고 마디에서만 스파이크로 튄다 → 식(3)의 hL = JLT(M̃LJ̇Lq̇L + h̃L) 중 코리올리 유사 항이 사실상 누락되거나 델타 스파이크로 들어간다. §6-①의 확인 대상.

3.2 동역학 (Dynamics)

관절 각도 기반 동역학 (Euler-Lagrange):

ẋθ = [q̇θ; q̈θ] = [q̇θ; Mθ−1(−hθ + JθTu + Δ)] =: fθ(xθ, u, Δ) (2)
기호의미
xθ = [qθT q̇θT]T ∈ ℝ8 시스템 상태
u = [TU FB FA FK]T ∈ ℝ4 제어 입력 (swing torque + 유압 실린더 force)
Mθ(qθ) ∈ ℝ4×4 질량 행렬
hθ(qθ, q̇θ) ∈ ℝ4 Coriolis-원심력 + 중력 합성항
Δ ∈ ℝ4 총괄 외란 (lumped disturbance)
수식 상세 전개

Mθ와 hθ의 원소별 전개, 변수 색깔 구분(측정/CAD/미지), FL과의 연결은 별도 노트 참조:

02_research/필드로봇/굴착기 동역학 M과 h 수식 해부 · 굴착기 동역학 M과 h 수식 해부

실린더 변위 기반 동역학 (local planning에서 사용):

ẋL = [q̇L; q̈L] = [q̇L; ML−1(−hL + u + ΔL)] =: fL(xL, u, ΔL) (3)

여기서 ML(qL) = JLTM̃LJL, hL = JLT(M̃LJ̇Lq̇L + h̃L), ΔL = JLTΔ.

대응: 식(2)의 M(팔이 얼마나 무거운가)과 h(중력·회전 관성 힘)를 계산하는 코드가 dynamics.py에 있고, 실제로 3군데서 사용 중입니다:

  1. 국소 제어 최적화의 “지금 자세에서 중력이 이만큼 당긴다” 항

식(8)은 minβk,T로 T가 결정변수다. 원문도 못박는다 — “where βk is the k-th control point ... and T is the time cost for complete traversal”. T가 비용에 어떻게 들어가는지 풀면 구조가 드러난다.

s = t/T 로 두면 곡선 모양 β 는 T 와 무관하고

  q̇_L = (1/T)·q′(s)      q̈_L = (1/T²)·q″(s)

  u = M_L q̈_L + h_L = (1/T²)·A(s)  +  G(s)
                       └관성·코리올리┘  └중력┘
                       (T에 반비례)    (T와 무관 ← 핵심)

  J(T) = ∫₀ᵀ ½uᵀW_u u dt = a/T³ + b/T + c·T
         a=½∫AᵀW_uA ds,  b=∫AᵀW_uG ds,  c=½∫GᵀW_uG ds

  dJ/dT = 0  →  c·T⁴ − b·T² − 3a = 0
  T* = √( [ b + √(b² + 12ac) ] / (2c) )

붐을 들고 있는 한 가만히 있어도 힘이 든다(G는 T에 안 줄어든다). 그래서 빨리 가면 관성이 a/T³로 폭증하고, 느리게 가면 중력을 c·T만큼 더 오래 지불한다. 논문의 T 최적화는 이 균형점을 찾는 것이고, 우리가 버린 것이 그 균형이다.

다만 무해할 가능성이 실재한다: 관성이 중력에 비해 작은 저속 영역(a≈0)이면 T*가 속도 상한 코너로 붙으므로, 논문의 최적화기도 우리와 같은 답(= 허용 범위 내 최대 속도)을 낸다. E85의 0.25~0.5 m/s는 그 영역일 개연성이 있다. 추측으로 남기지 말고 계산으로 판정할 것 → §6.2

(c) 역설적으로 유리한 점 1개 — 논문의 유일한 명시적 가정 Δ̂k+1 = Δ̂k는 N=50이면 1초간 토양 반력이 일정하다는 강한 가정이다. N=1이면 50ms만 필요하므로 오히려 더 안전하다. 뒤집으면 N을 늘릴 때 이 가정의 부담도 같이 커지므로, N 확대와 외란 예측 모델 개선은 함께 검토해야 한다.

② 제어 주기 — 여기에 기회가 있음

논문:   주기 20ms인데 연산이 21.7~30.2ms  → 주기를 못 지켜 33~46Hz로 밀림 (빠듯)
APEX:   주기 50ms인데 연산이 p95 7ms      → 예산의 14%만 사용 (여유 86%)

연산 예산이 86% 남은 채로 N=1을 쓰고 있다. N을 늘릴 여력이 이미 확보되어 있다는 뜻이며, ①의 근시안 문제를 푸는 데 추가 하드웨어가 필요 없다. 희소 구조 유지 시 N=10 정도는 50ms 예산 내 예상 — 정확한 수치는 실측 필요.

④ 속도 명령 — 환산은 타당, 그러나 제약이 물리적으로 강제되지 않음

외란 추정 (Disturbance Estimation)

모멘텀 기반 외란 추정(momentum-based disturbance estimation):

Δ̂ = KE[p − p(0) − ∫0t(JθTu + CθTq̇θ − Gθ + Δ̂)dτ], p = Mθq̇θ (11)

Ṁθ = Cθ + CθT 성질을 활용하면, 실제 외란 Δ의 저역통과 필터(low-pass filter)로 작동:

Δ̂̇ = KE(Δ − Δ̂)

실린더 변위 기반 추정값: Δ̂L = JLTΔ̂ = [Δ̂U Δ̂B Δ̂A Δ̂K]T

④의 단서: 버킷은 4절 링크(사다리꼴)라 삼각형 3파라미터 형태로 맞지 않는다. 버킷만 표를 유지하되, ①에서 “표에서 J̇L을 뽑는다”로 확인되면 np.interp → CubicSpline(C² 연속)으로 교체해 J̇의 계단·스파이크를 없앤다.

논문은 이 부분을 어떻게 했나 (원문 대조 2026-08-14)

원문 §II.A는 매핑을 “The nonlinear, bijective mapping between qθ and qL can be derived by solving closed-chain kinematics” 한 문장으로만 선언하고, 식(1)의 gL, gθ, JL, Jθ를 유도된 함수로 둔 뒤 where J_L, J_θ are corresponding Jacobian matrices 한 줄로 넘어간다 — 구체적인 식은 싣지 않았다. 링크 치수·핀 좌표가 HX300L의 실제 CAD 형상이라 공개하지 않은 것으로 보인다.

따라서 “논문이 우리와 다르게 처리했다”기보다, 논문은 해석해 안에 비선형성을 넣어두고 보여주지 않은 것이고 우리는 그 비선형성을 실측 표로 직접 담은 것이다. 버킷의 비비례성(벌리는 쪽과 오므리는 쪽 기울기 2배 차이)도 4절 링크 폐쇄 조건의 비선형성이라 해석해 안에 이미 들어 있다. 다만 4절 링크 위치해석은 닫힌 해가 존재하므로(반각 탄젠트 치환 / 코사인 법칙 2회), “해석적으로 안 풀린다”는 것은 사실이 아니다.

실질적 차이는 J̇까지 필요하다는 점(식 3의 hL)에 있다. 해석해는 미분해서 그대로 얻지만, 40칸 이산 표에서는 2차 미분에 해당하는 양을 뽑아야 한다.

기종도 다르다 — 논문은 HX300L(~30t급), APEX는 E85(~8t급). 표가 “실측이라 실제와 정의상 일치”한다는 표현은 정확히는 AGX 시뮬레이터의 E85 URDF 기하와 일치한다는 뜻이며, 실기 일치와는 별개다.

6.2 Phase 1·3 시간 배분(T) 단순화의 타당성 검증

배경과 유도는 §3.3 식(7)(8)(9) 콜아웃의 「🔍 시간 배분 단순화 재검토」 참조. 요지는 “우리 방식이 틀렸다”가 아니라 “맞는지 아직 안 재봤다”이며, 재는 데 드는 계산이 스칼라 1개짜리 닫힌 해라는 것이다.

⓪ 착수 전 반드시 확정할 것 (코드 확인, 5분)

이게 정해지지 않으면 아래 ⑤~⑦ 전부가 잘못된 전제 위에 선다.

확인 항목왜 중요한가
“시간만 재배분”의 정확한 의미 — (A) T = Σ(구간길이 / 구간속도)로 T가 속도 상한의 결과인가, (B) 전체 T는 외부 고정이고 구간 배분만 조정하는가 (A)면 ⑤의 T_cap 정의가 그대로 성립한다. (B)면 T가 물리와 무관한 상수라는 뜻이라 격차가 더 크고, ⑤의 비교 대상 자체를 다시 세워야 한다
0.5 / 0.25 / 0.5의 정체 — phase 1/2/3에 각각 대응하는가, 아니면 phase 1(또는 3) 내부의 구간별 값인가 phase 대응이면 속도 불연속이 논문이 매끄럽게 하라고 명시한 바로 그 두 지점에서 발생한다 (⑦의 판정이 달라짐)
속도 상한 0.5/0.25m/s의 출처 안전 기준인지, 액추에이터 한계 환산인지, 경험값인지. ⑤에서 T*가 더 느리게 나왔을 때 상한을 바꿔도 되는지가 여기서 갈린다

⑤ T* 계산 후 현재 T와 대조 — 이 절의 핵심 작업

곡선 모양 β를 고정한 채로는 T가 스칼라 하나이고 닫힌 해가 있다. 새 솔버·재최적화 불필요.

1) 고정된 Bernstein 곡선을 임의의 기준 T₀ 로 샘플링 (s ∈ [0,1], 균등 N점)

2) 역동역학 2회 평가로 A, G 분리:
     G(s) = u |_{q̇=0, q̈=0}            ← 중력만 (정적 유지력)
     A(s) = T₀² · ( u|_{T₀} − G(s) )   ← 나머지 = 관성·코리올리

3) 사다리꼴 적분 3개:
     a = ½∫₀¹ AᵀW_u A ds
     b =  ∫₀¹ AᵀW_u G ds
     c = ½∫₀¹ GᵀW_u G ds

4) T* = √( [ b + √(b² + 12ac) ] / (2c) )

5) T_cap = (현재 방식이 산출하는 실제 소요시간)  ← ⓪-(A)/(B)에 따라 정의
6) 비율 r = T* / T_cap 출력

판정 기준 (이 표대로 결론을 적을 것):

r = T*/Tcap의미조치
0.9 ~ 1.1 속도 제약이 실제로 binding — 우리 선택이 논문 해와 사실상 일치 §3.3 판정 🟡 → 🟢 승격, 근거 수치와 함께 종결. 코드 변경 없음
r > 1.1 불필요하게 빨리 달려 관성력을 낭비 중 T를 T*로 늘린다. 힘 여유가 생기므로 §3.4 “24% 경고”와 §3.2 Δ̂ 포화가 함께 줄어드는지 확인
r < 0.9 더 빨리 갈 수 있는데 못 가는 중 사이클 타임 손해. ⓪의 “속도 상한 출처”를 근거로 상한 재검토

하지 말 것:

  • β(곡선 모양)까지 같이 최적화하지 말 것. 식(8)의 완전한 minβ,T를 재현하려 들면 범위가 폭발하고 §3.3의 검증된 형상(운전자 관찰로 고친 2건 포함)이 깨진다. 이번 작업은 β 고정, T만이다.
  • W_u를 임의로 정하지 말 것. 현재 코드에 힘 가중이 없다면 단위행렬로 두고 그 사실을 결과에 명시한다. 임의 가중은 T*를 원하는 값으로 만들 수 있어 판정이 무의미해진다.
  • ⓪이 미확정인 채로 진행하지 말 것.

⑥ 제약 공간 정합 — 팁 속도 상한이 실린더 속도 상한을 넘는 구간 찾기

현재 상한은 Cartesian 팁 속도인데, (10d) 유량 제약과 논문 식(8)의 속도 제약은 실린더 속도 q̇L이다.

전체 궤적을 훑으며 각 시점에서
    q̇_L = J_θ(q_θ) · q̇_θ   (또는 표/피팅에서 얻은 dL/dθ 적용)
를 계산하고 아래를 출력:

  - max |q̇_L| 을 축별로  →  실린더 속도 상한 대비 몇 %인가
  - Σ abs(q̇_L) 의 시계열 →  (10d) 펌프 유량 한계를 넘는 구간 비율
  - 위반 구간의 자세(θ_B, θ_A, θ_K) 기록  →  어떤 자세에서 터지는가

판정: 위반 구간이 0%면 팁 속도 상한이 충분히 보수적이라는 뜻이므로 이 격차는 닫는다. 0%가 아니면, 전역 기준궤적이 실린더 공간에서 이미 실현 불가능하다는 뜻이고 → 국소 MPC가 매 스텝 밀어내며 따라가는 중 → §3.4 “24% 경고”의 원인 후보로 확정(기존 후보인 “미보정 힘 한계 수치”와 병기).

⑦ 저크(§5 한계 ⑤)의 원인 판별 — 새 실험 불필요, 기존 로그 재분석

⑤ 덜컹거림의 원인으로 ④ MPC horizon 단순화를 1순위로 적어두었으나, 경쟁 가설이 생겼다: 0.5/0.25/0.5 구간별 상수 속도의 경계 불연속.

기존 주행 로그에서 저크(팁 가속도의 시간 미분 또는 q̈_L 변화율)를 뽑고,
phase 전환 시각에 마커를 찍어 분포를 본다.

  ├ 저크 스파이크가 phase 전환 시점에 국소적으로 몰림
  │     → 원인 = 속도 스케줄 불연속.
  │       조치: 경계에서 속도가 이어지도록 시간 배분에 C¹ 연속 조건 추가
  │             (논문의 "boundary values chosen ... smooth" 에 해당)
  │
  └ 저크가 주행 내내 고르게 깔림
        → 원인 = ④ MPC horizon. 기존 1순위 유지

판정 기준: phase 전환 ±0.2초 구간이 전체 저크 에너지의 50% 이상을 차지하면 속도 스케줄이 주원인.
