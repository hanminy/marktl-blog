한 줄 요약

로봇 파운데이션 모델을 RL로 엔드투엔드 학습하는 건 아직 어렵다. 대신 스페셜리스트(작은 모델 + 샘플효율 RL)와 제너럴리스트(VLA)를 양방향으로 순환시켜라 — 제너럴리스트는 RL 토큰으로 스페셜리스트의 탐색을 돕고, 스페셜리스트는 증류로 제너럴리스트를 끌어올린다.

핵심 장면 분석

장면 1 (02:25): 물리 세계의 파운데이션 모델 — 왜 로봇이 필요한가

발표의 출발점. "집 청소하고, 빨래 개고, 저녁 차려줘"라고 LLM에게 부탁하면 실행 계획 텍스트만 돌아온다("It sounds like you have a busy evening ahead!"). 우리가 원하는 건 로봇이 "On it!"이라고 답하고 실제로 수행하는 것. 이는 단순 pick-and-place가 아니라 새로운 환경·물체·시나리오로의 일반화 + 다단계 오픈엔디드 지시 수행을 요구한다.

장면 2 (04:20): 파운데이션 모델 학습의 해부

로봇이 아닌 일반 파운데이션 모델(LLM)의 표준 레시피를 먼저 해부한다.

  • Pre-training: 웹 대규모 데이터(Common Crawl, Wikipedia 등) 선별·큐레이션 → 특정 과제를 푸는 게 아니라 사실과 패턴을 많이 아는 상태를 만든다.
  • Post-training/alignment: 고품질 SFT 데이터셋 + 파인튜닝 알고리즘 설계(예: RLHF, PPO+RM) → 아는 것을 실제 과제 해결에 배치하는 단계.

핵심 대비: pre-training = 지식, post-training = 그 지식을 써서 과제를 푸는 능력.

장면 3 (04:50): 로봇 파운데이션 모델을 위한 유사 레시피

같은 구조를 로봇에 옮긴다. 다양한 로봇 데모 데이터로 pre-training(VLA: SigLIP 400M + Gemma 2.6B + action expert 300M) → post-training에서 SFT뿐 아니라 자동화된 RL을 적용. Levine의 주장: 높은 성공률·인간 수준의 속도를 원한다면 이 RL 단계가 필수다. 다만 "구조는 유사하되 구현은 LLM과 매우 다르다"고 못 박는다.

장면 4 (06:50): 문제 — 지도학습만으로는 "그럭저럭"에서 멈춘다

지도학습 pre-training의 장단점을 명시적으로 나열한다.

  • (+) 모델이 많은 것을 안다 / 일반화한다 / 언어 지시를 따른다
  • (−) 많은 것에 "OK" 수준일 뿐 / 느리다

느린 이유가 중요하다. 단순히 동작 속도가 아니라 실수하고 그 실수를 복구하느라 사이클 타임이 길어진다는 것. RL 단계의 목표는 이 두 결핍을 메우는 것 — 원하는 과제를 마스터하고 빠르게 수행. 지도학습(지식·일반화)과 RL(숙달)은 대체재가 아니라 상보재다.

장면 5 (09:30): 왜 어려운가 — 실세계 RL과 3요소의 결합

"목표가 실세계 과제를 완벽히 해내는 것이라면, 실세계에서 학습해야 한다." 시뮬레이션/샌드박스에서 배우면 결국 그 샌드박스에 대해 배울 뿐이다.

RL in the real worldRL in sim/sandbox
장점실세계 자체를 학습병렬화 가능, 비싼 알고리즘 사용 가능
단점매우 샘플효율적인 알고리즘 필요시뮬레이터에 넣은 것만 학습

오른쪽 아래 벤 다이어그램이 이 발표의 문제 정의다: big model × sample-efficient RL × hard task(근본적으로 새로운 전략 필요). 둘까지는 괜찮지만 셋의 결합이 극도로 어렵다. 요리 비유 — 야채 써는 법을 익히려면 결국 실제로 썰어봐야 한다.

장면 6 (10:20): 스페셜리스트 RL 레시피 — RLPD

파운데이션 모델을 쓰지 않지만 잘 작동하는 기준선. 알고리즘은 RLPD(soft actor-critic 기반 + 데모를 리플레이 버퍼에 섞는 off-policy 방식). Levine 본인 표현으로 "알고리즘이 뭔지는 별로 중요하지 않다 — 충분히 샘플효율적인 actor-critic이면 된다".

  • 관측: wrist 카메라 이미지 + 사전학습 비전 인코더
  • 보상: 이진 이미지 분류기가 주는 희소 보상(과제 완료 여부)
  • 옵션: 인간 개입(corrective demonstration) — off-policy라 리플레이 버퍼에 그냥 넣으면 되고, 탐색에 큰 도움

장면 7 (11:45): SERL — 실세계 스페셜리스트 학습 데모

오픈소스 프레임워크 SERL. 왼쪽은 자동차 대시보드 조립을 반복 연습하는 학습 과정(20배속, 누적 11분 08초), 오른쪽은 학습 완료 후 1배속 자율 실행. 플라스틱 커넥터를 정렬해 정확한 위치에 꽂아야 하는 난이도 높은 과제다. 몇 시간이면 학습이 끝난다.

장면 8 (12:45): 스페셜리스트 결과 — 100% 성공률, 사이클타임 절반

타이밍벨트 조립, IKEA 조립, 물체 뒤집기, 젠가 whipping 등으로 확장. 타이밍벨트 데모에서는 연구자가 로봇을 물리적으로 교란해도 복구한다.

  • 실세계 이미지로부터 과제당 1~2시간 학습
  • 성공률 100% (학습된 특정 환경 기준)
  • 사이클 타임(RL vs BC): 물체 재배치 7.53 vs 18.94초, 케이블 라우팅 4.08 vs 13.58초, PCB 부품 삽입 5.22 vs 10.14초 — BC 기준선에는 데이터 총량을 맞춰 더 많이 줬는데도 RL이 절반 이하

한계: pre-training이 없다 → 일반화의 기반이 없고, 학습 환경 밖으로는 나가지 못하는 특화 정책이다.

장면 9 (13:55): 스페셜리스트 → 제너럴리스트 증류 (RLDG)

Charles Xu 등의 RLDG. Ethernet/VGA/USB 커넥터별로 RL 스페셜리스트를 각각 학습(1단계) → 정책 롤아웃으로 경험 수집(2단계) → OpenVLA(LoRA 파인튜닝)와 Octo(전체 파인튜닝) 에 증류(3단계). 개별 스페셜리스트는 일반화하지 못하지만, 증류된 제너럴리스트는 처음 보는 커넥터에도 작동한다.

가장 중요한 발견: RL이 만든 데이터가, 같은 개수의 성공한 사람 데모보다 로봇 파운데이션 모델의 학습 데이터로 더 효과적이다. (RL은 마르코프 정책을 학습하기 때문)

장면 10 (15:10): 역방향 질문 — 제너럴리스트가 스페셜리스트를 도울 수 있나?

앞의 레시피는 한쪽 방향뿐이라 불만족스럽다. 스페셜리스트는 제너럴리스트를 개선하지만, 제너럴리스트는 다음 스페셜리스트의 RL 학습을 전혀 쉽게 만들어주지 않는다. RL은 대규모 사전학습의 혜택 없이 혼자 성공해야 한다. 화살표를 되돌려 순환 고리를 만드는 것이 다음 주제.

장면 11 (16:35): RLT — 로봇 파운데이션 모델에 "RL 토큰" 붙이기

Physical Intelligence의 RLT (RL Token) — pi.website/research/rlt

구조:

  1. π*0.6 VLA(SigLIP 400M + Gemma 4B)의 내부 표현을 cross-attention 인코더/디코더(오토인코더 형태)로 압축 → RL 토큰 1×2048 (이미지 임베딩 N×2048에서 축약)
  2. 이 RL 토큰과 VLA가 내놓을 액션 청크를 함께 작은 RL actor & critic에 입력
  3. RL 알고리즘은 "파운데이션 모델은 지금 이렇게 보고, 이렇게 행동하려 한다"를 알고 시작 → 모를 땐 그대로 따라가며 탐색하고, 익숙한 영역이면 개선
  4. 출력 액션 청크가 파운데이션 모델 출력과 비슷하도록 BC 정규화 항 추가 → "더 나은 행동을 배우지 못했다면 기본 모델을 따르라"

장면 12 (17:45): RLT 실험 설계 — 가장 정밀한 단계만 RL

긴 호흡의 과제 전체를 RL로 학습하지 않는다. 상위 정책이 과제를 단계로 분할하고, 가장 까다로운 한 단계(예: 드라이버로 나사 조이기)만 RL로 파인튜닝한다. "먼저 base model을 돌리고, 가장 정밀한 단계를 RL로 파인튜닝한다."

장면 13 (18:30): RLT 대상 과제들

장면 15 (22:00): RL 데이터를 제너럴리스트에 어떻게 넣을까

마지막 주제. 증류할 데이터 선택의 딜레마:

  • 최종 정책 데이터만 사용: (+) 전부 좋은 데이터라 BC로 충분 / (−) RL이 수집한 데이터 대부분이 버려짐
  • RL 중 수집한 전체 데이터 사용: (+) 데이터가 많고 변동성·실수·복구가 포함되어 일반화와 회복력에 유리 / (−) 대부분이 나쁜 데이터

목표: 좋은 데이터와 나쁜 데이터를 섞어서 학습할 수 있다면, 별도 actor 없이 로봇 파운데이션 모델 자체를 RL의 actor로 쓸 수 있다.

장면 16 (24:15): CFGRL — 유도(guidance)를 정책 개선 연산자로

발표 중 유일한 수식 슬라이드. Kevin Frans, Seohong Park, Pieter Abbeel, Sergey Levine, Diffusion Guidance Is a Controllable Policy Improvement Operator.

$$J(\pi_\theta) = \mathbb{E}_{\tau \sim p(\tau|\pi_\theta)}\left[\sum_t \gamma^t r(s_t, a_t)\right] - \beta\,\mathbb{E}_{s \sim p_\pi(s)}\left[D_{\mathrm{KL}}\!\left(\pi_\theta(a|s)\,\|\,\hat{\pi}(a|s)\right)\right]$$

  • $\pi_\theta$ = "좋은" 데이터에 맞는 정책, $\hat\pi$ = 모든 데이터에 맞는 참조 정책
  • 이는 PPO와 정규화된 offline RL의 공통 골격

핵심 통찰: 이 목적함수는 policy gradient(PPO, SAC actor)로만 최적화되는 게 아니라, 디퓨전의 classifier-free guidance(CFG)로도 달성 가능하다.

수렴 해의 형태: $$\pi(a|s) \propto \hat{\pi}(a|s)\,\exp(A(s,a))^{1/\beta}$$

여기서 이진 최적성 변수 $o$ 를 도입한다($f$ = 지수함수, $Z(s)$ = 분배함수): $$p(o|s,a) = f(A(s,a))/Z(s), \qquad \pi(a|s) \propto \hat{\pi}(a|s)\,p(o|s,a)$$

스코어 함수로 쓰면 참조 정책의 스코어 + $p(o|s,a)$의 액션에 대한 기울기 합이 되고, 베이즈 정리로 재배열하면 CFG의 형태와 정확히 일치한다. CFG는 학습 알고리즘이 아니라 추론 시점 방법이라는 점이 요점 — 학습은 전체 데이터로 하고, 개선은 샘플링 때 일어난다.

장면 17 (25:50): 시각적 해석 — 좋은 데이터의 모드로 줌인

수식의미
Unconditional Policy$\hat\pi(a\s)$전체 데이터 분포 (좋은 것 + 나쁜 것)
Optimality Conditioned$\hat\pi(a\s,o) \propto \hat\pi(a\s)p(o\s,a)$$o$로 조건화한 분포
Optimality Guided$\hat\pi(a\s)\,p(o\s,a)^w$좋은 데이터의 모드로 줌인

학습 시 최적성 지시자를 랜덤 드롭아웃 → 모델은 "$o$=참이면 좋은 데이터처럼, $o$=거짓이면 그렇지 않게" 행동하는 법을 배운다. 샘플링할 때 단순히 $o$=참으로 조건화하는 게 아니라 guidance weight $w$로 증폭한다.

소규모 실험에서 advantage-weighted regression(AWR)을 능가한다. 이유가 명쾌하다 — AWR은 배치의 다수 샘플에 가중치 0을 주지만, CFGRL은 배치의 모든 원소를 사용하므로 훨씬 안정적이다.

장면 18 (26:35): 조건화를 대규모 정책 추출로 — π*0.6

CFGRL의 진짜 이점은 디퓨전 기반 로봇 파운데이션 모델에 그대로 꽂힌다는 것. π*0.6 VLA는 다양한 로봇 데이터 + 서브태스크 명령("wait for the espresso to dispense", "pick up the pillow") + 멀티모달 웹 데이터를 받고, language와 advantage를 함께 조건으로 넣는다. (pi.website/blog/pistar06)

장면 19 (27:05): π*0.6 전체 아키텍처

  • 정책: π*0.6 VLA (SigLIP 400M + Gemma 4B) + action expert(860M), 언어 서브태스크·웹 데이터·chain-of-thought 입력, 이산/연속 액션 출력
  • 가치함수: 별도의 사전학습 VLM (SigLIP 400M + Gemma 270M) + value head
  • 어드밴티지: $A(o,a) = r_{t:N} + V(o_{t+N}) - V(o_t)$ → 이진화 $A(o,a) > \epsilon$ 후 정책에 조건으로 투입

우측 그래프가 인상적이다 — 셔츠 접기 중 "왼팔이 올라가며 개어놓은 셔츠를 구겨버림"에서 value가 급락하고, "복구 후 다시 접음"에서 회복한다. 즉 가치함수가 해석 가능한 진행도 지표로 작동한다. (Chelsea Finn의 후속 발표에서 상세히 다룬다고 언급)

장면 20 (27:50): π*0.6 정량 결과

4개의 장기 호흡 과제(빨래 개기 2종, 에스프레소 만들기, 박스 조립)에서 시간당 성공 횟수 비교. 막대 순서는 π0.5 Pretrain → π0.6 Pretrain → OfflineRL Pretrain(데모 데이터로 offline RL 사전학습) → OfflineRL + SFT(대상 과제 데모로 파인튜닝) → Ours(RL 반복). 4개 중 3개에서 처리량 2배 향상. 에스프레소·박스 접기 데모는 몇 시간 연속 무중단 실행됐다.

장면 21 (28:15): π0.7 — 증류 중심 로봇 파운데이션 모델

모든 조각을 하나로 합친 통합 모델. 데모 데이터 + 모든 스페셜리스트의 자율 데이터를 함께 학습하고, 학습 시 언어 지시·서브골 이미지·에피소드 메타데이터(품질 별점, 길이) 를 조건으로 준다. 추론 시에는 상위 정책·월드 모델·원하는 메타데이터로 프롬프팅. RL로 학습했던 과제들을 하나의 모델이 동일 수준으로 전부 수행한다 — 스페셜리스트의 제너럴리스트 증류가 성립함을 보인 결과. (pi.website/blog/pi07)

장면 22 (29:15): Takeaways

  • 로봇 파운데이션 모델의 엔드투엔드 RL 학습은 (아직) 상당히 어렵다
  • 그러나 RL은 개별 스페셜리스트가 새로운 전략이 필요한 어려운 과제를 배우는 데는 매우 잘 작동한다
  • 제너럴리스트 모델이 스페셜리스트를 도울 수 있다 (RL 토큰)
  • 스페셜리스트가 제너럴리스트를 도울 수 있다 (증류)

장면 23 (29:32): 결론 — 스페셜리스트↔제너럴리스트 증류 순환

미래에는 엔드투엔드 RL도 가능해질 것이고 사용도 하겠지만, 스페셜리스트 방식과 함께 쓰게 될 것이다(스페셜리스트가 훨씬 빨리 학습하므로). 제안하는 순환 레시피:

  1. 대규모 (아마도 offline) RL로 로봇 파운데이션 모델 학습
  2. 그 모델을 초기화·부트스트랩으로 삼아 스페셜리스트가 복잡한 과제를 빠르게 학습
  3. 거기서 나온 데이터를 다시 제너럴리스트로 증류
  4. → 1로 반복

주요 내용 요약

핵심 포인트

  • 지도학습 pre-training과 RL post-training은 상보적이다. 전자는 지식과 일반화, 후자는 특정 과제의 숙달과 속도를 준다. 둘 다 없으면 파운데이션 모델이라 부를 수 없다.
  • RL post-training은 실세계에서 해야 한다. post-training은 분포 변화를 가장 적게 감내할 수 있는 단계이기 때문. 시뮬레이터에서 배우면 시뮬레이터를 배운다.
  • 어려움의 본질은 big model × sample-efficient RL × hard task의 3중 결합. 둘까지는 기존 기법으로 되지만 셋은 미해결에 가깝다.
  • 스페셜리스트 RL(RLPD + SERL)만으로도 과제당 1~2시간, 성공률 100%, 사이클타임 절반이 나온다. 다만 일반화가 없다.
  • RL 데이터 > 동일 개수의 성공 데모 — 파운데이션 모델 학습 데이터로서 RL 롤아웃이 사람 데모보다 효과적이다.
  • RL 토큰으로 제너럴리스트의 표현·행동을 스페셜리스트 RL에 주입하면, 15분 분량 데이터로 base policy를 크게 뛰어넘고 사람 원격조작보다 빨라진다.
  • CFG = 정책 개선 연산자라는 재해석 덕분에, 좋은 데이터와 나쁜 데이터를 모두 써서 디퓨전 기반 VLA를 직접 RL로 개선할 수 있다.
  • 최종 그림은 단방향 파이프라인이 아니라 제너럴리스트 ↔ 스페셜리스트 순환이다.

기술적 내용

  • RLPD: soft actor-critic 기반, 데모를 리플레이 버퍼에 포함하는 off-policy 샘플효율 알고리즘. 관측은 wrist 카메라 + 사전학습 비전 인코더, 보상은 이진 이미지 분류기 기반 희소 보상, 인간 개입 보정은 선택적.
  • SERL / HIL-SERL: 실세계 로봇 RL 오픈소스 프레임워크. 스페셜리스트 정책 전용.
  • RLDG: RL 스페셜리스트 → OpenVLA(LoRA) / Octo(full FT) 증류. 미지의 커넥터로 일반화 확보.
  • RLT: cross-attention 인코더-디코더로 VLA 내부 표현을 1×2048 RL 토큰으로 압축. RL actor/critic에 (RL 토큰 + VLA 액션 청크) 입력, 출력 청크에 BC 정규화. 어블레이션에서 RL 토큰 제거가 가장 치명적.
  • *π0.6**: 정책 = SigLIP(400M) + Gemma(4B) + action expert(860M), 가치함수 = 별도 사전학습 VLM SigLIP(400M) + Gemma(270M) + value head. advantage를 이진화해 조건으로 투입(RECAP 계열).
  • π0.7: 데모 + 전 스페셜리스트 자율 데이터 통합 학습. 언어 지시·서브골 이미지·에피소드 메타데이터(품질/길이)를 조건화, 추론 시 원하는 메타데이터로 프롬프팅.
  • 엔지니어링 포인트: 액션 청킹은 필수(제거 시 개선 실패), 보상 설계는 이진 분류기로 단순화, 장기 과제는 상위 정책이 단계 분할 후 병목 단계만 RL.

수학적 내용

KL 정규화 RL 목적함수: $$J(\pi_\theta) = \mathbb{E}_{\tau \sim p(\tau|\pi_\theta)}\left[\sum_t \gamma^t r(s_t, a_t)\right] - \beta\,\mathbb{E}_{s \sim p_\pi(s)}\left[D_{\mathrm{KL}}\!\left(\pi_\theta(a|s)\,\|\,\hat{\pi}(a|s)\right)\right]$$

수렴 해 ($\beta$는 라그랑주 승수 역할의 온도): $$\pi(a|s) \propto \hat{\pi}(a|s)\,\exp(A(s,a))^{1/\beta}$$

이진 최적성 변수 $o$ 도입: $$p(o|s,a) = \frac{f(A(s,a))}{Z(s)}, \qquad \pi(a|s) \propto \hat{\pi}(a|s)\,p(o|s,a)$$

스코어 함수 분해 → 베이즈 정리 재배열 → classifier-free guidance와 동형: $$\hat{\pi}(a|s)\,p(o|s,a)^{w}$$

π*0.6의 어드밴티지 정의와 이진화: $$A(o,a) = r_{t:N} + V(o_{t+N}) - V(o_t), \qquad \mathbb{1}[A(o,a) > \epsilon]$$

파인만식 설명

  • 파운데이션 모델 vs RL — 요리학교에서 온갖 요리의 이론과 기본기를 배운 사람(pre-training)과, 자기 가게에서 김밥 하나를 만 번 말아본 사람(RL)의 차이다. 전자는 뭐든 그럭저럭 하지만 어느 것도 빠르고 완벽하진 않고, 후자는 김밥만 아주 잘한다. 좋은 요리사는 둘 다 거친 사람이다.
  • 왜 실세계에서 연습해야 하나 — 농구 자유투를 방 안에서 이미지 트레이닝으로 아무리 연습해도, 결국 진짜 체육관 마룻바닥과 진짜 공으로 던져봐야 한다. 시뮬레이터에서 잘하게 되면 "시뮬레이터 잘하는 법"을 배운 것이다.
  • RL 토큰 — 신입에게 무작정 "알아서 해보라"고 하는 대신, 베테랑을 옆에 앉혀 놓고 "지금 상황은 이렇고, 나라면 이렇게 하겠다"고 계속 알려주는 것. 신입은 모를 땐 베테랑을 따라가고, 자기가 더 나은 방법을 찾았을 때만 벗어난다. 무작위로 헤매는 것보다 훨씬 빨리 는다.
  • classifier-free guidance로 RL하기 — 잘한 시도와 못한 시도를 전부 모아놓고, 각 시도에 "이건 잘된 것 / 이건 잘 안 된 것"이라는 스티커를 붙여 통째로 학습시킨다. 나중에 실제로 행동할 때 "잘된 것 스티커 쪽으로 더 세게 밀어달라"고 요청하면(guidance weight), 모델이 좋은 사례들이 몰려 있는 중심부로 알아서 이동한다. 못한 데이터를 버리지 않는 게 핵심 — 실패도 "이쪽은 아니다"라는 정보이기 때문이다.
  • AWR보다 안정적인 이유 — AWR은 시험지 100장 중 잘 본 5장만 보고 공부하는 것이고, CFGRL은 100장을 다 보되 점수를 라벨로 붙여서 보는 것이다. 후자가 데이터를 낭비하지 않고 학습도 흔들리지 않는다.
  • 탐색(exploration) 문제 — 아기는 구멍에 물건을 넣을 때 구멍을 보고 그쪽으로 손을 뻗지, 손을 무작위로 떨지 않는다. 해법은 파운데이션 모델을 행동 사전확률(prior) 로 쓰는 것이고, 한발 더 나아가 언어 입력을 바꿔가며 "의미 공간"에서 탐색하는 것이다 — 액션 값을 랜덤하게 흔드는 것보다 훨씬 나은 탐색 공간이다.

질의응답 (29:38~)

Q. 지금의 RL 알고리즘은 USB를 구멍에 넣을 때 사람처럼 구멍을 보고 다가가는 게 아니라 궤적 내내 무작위로 떤다. 근본적으로 빠진 요소가 있는가? play data나 world model이 도움이 될까?

A. 바로 이 지점이 제너럴리스트 모델이 유용한 도구가 되는 지점이다. 로봇 파운데이션 모델을 prior로 쓰면 된다. RLT에서 BC 항이 하는 역할이 정확히 그것 — 잘 모를 때 RL actor가 제너럴리스트와 유사한 방식으로 탐색하게 만든다. 참조 행동 근처에 머무르므로 진짜 새로운 해법을 찾는 데는 좋지 않지만, 파운데이션 모델이 이미 많이 안다고 믿는다면 매우 좋은 탐색 방법이다. 더 나아가 탐색 중 언어 입력을 바꿔가며 의미 공간에서 탐색할 수 있고, 이는 액션을 무작위로 흔드는 것보다 훨씬 나은 공간이다(관련 최근 연구 진행 중). 결론: 제너럴리스트는 탐색을 위한 훌륭한 행동 사전확률이며, 우리는 이를 활용해야 한다.

장면 9 심화 — RLDG: "잘하는 전문가를 갈아서 만능 모델에 먹이기"

이 장면이 나온 이유

장면 8에서 스페셜리스트 RL이 성공률 100%, 사이클타임 절반을 달성했지만 한계가 명확했다 — 자기가 연습한 그 커넥터, 그 위치, 그 조명에서만 작동한다. 반대로 OpenVLA 같은 제너럴리스트는 처음 보는 물건에도 시도는 하지만 어설프고 느리다.

RLDG의 질문: "스페셜리스트의 손기술을, 제너럴리스트의 일반화 능력에 옮겨 심을 수 있나?"

3단계 파이프라인 (슬라이드 하단 구분선)

1단계 · RL Policy Training — 슬라이드에는 use case가 두 가지로 나뉜다.

  • Use case 1 — 과제별 전문가 분리: $\pi^{RL}_{Ethernet}$, $\pi^{RL}_{VGA}$, $\pi^{RL}_{USB}$ 를 커넥터마다 따로 학습. 각각 자기 커넥터만 100% 꽂는다.
  • Use case 2 — 한 과제 안에서 어려운 구간만 RL: 레고 조립 예시에서 집기(Grasp)는 사람 데모($\pi^{Human}_{Grasp}$), 삽입(Insert)만 RL($\pi^{RL}_{Insert}$). 쉬운 구간에 RL을 낭비하지 않는다.
연결점

Use case 2는 장면 12(RLT 실험 설계)의 "병목 단계만 RL"과 정확히 같은 사고방식이다. 이 아이디어가 RLDG 시점에 이미 등장했다.

2단계 · Experience Collection — 학습된 정책을 그냥 계속 돌린다(policy rollout). 사람이 조종하는 게 아니라 로봇이 혼자 반복 실행하며 $\mathcal{D}^{RL}_{Ethernet}$, $\mathcal{D}^{RL}_{USB}$, $\mathcal{D}^{RL}_{VGA}$ 를 쌓는다.

여기가 경제적으로 가장 중요한 지점이다. 사람 데모는 데이터 1시간에 사람 1시간이 들지만, RL 정책은 밤새 혼자 돌려도 된다. 데이터 수집 비용이 인건비에서 전기요금으로 바뀐다.

3단계 · Generalist Finetuning — 모은 데이터를 두 개의 오픈소스 VLA에 넣는다.

결과 — 슬라이드 오른쪽 영상

위는 training (1 of 3), 아래 둘은 unseen test connectors (학습 때 본 적 없는 커넥터). 각 스페셜리스트는 자기 커넥터 밖으로 한 발짝도 못 나가지만, 증류된 제너럴리스트는 처음 보는 커넥터도 꽂는다.

손기술은 스페셜리스트에게서, 일반화 능력은 VLA의 사전학습에서 온다. 파운데이션 모델이 이미 "커넥터란 대충 이렇게 생겼고 구멍에 맞춰 넣는 것"이라는 지식을 갖고 있었기에, 정밀 삽입 기술만 주입하면 새 커넥터로 전이된다.

"RL 데이터 > 같은 개수의 사람 데모"를 풀어쓰면

조건을 정확히 봐야 한다 — 개수가 같고, 둘 다 성공한 시도인데도 RL 데이터가 이긴다. 이유는 세 가지.

(1) 사람은 같은 상황에서 매번 다르게 행동한다 (비-마르코프)

"마르코프 정책"이란 "지금 보이는 화면만 보고 행동을 정한다"는 뜻 — 같은 화면이면 항상 같은 행동. 사람은 그렇지 않다. 똑같아 보이는 장면에서 어떤 날은 왼쪽, 어떤 날은 오른쪽으로 돌린다. 그럼 데이터에 "같은 사진 → 서로 다른 정답"이 섞인다.

BC는 이걸 평균 낸다. 왼쪽 30% / 오른쪽 70%를 평균 내면 어느 쪽도 아닌 애매한 방향이 나오고 커넥터는 안 꽂힌다(mode averaging). RL 정책은 정의상 상태의 함수라 이 모순이 구조적으로 없다.

(2) 사람 데모에는 망설임과 군더더기가 섞여 있다

"어… 여기쯤인가?" 하며 멈칫하는 구간이 그대로 데이터에 들어가고, 모델은 그 망설이는 습관까지 성실히 복제한다. 이것이 장면 4의 "지도학습 모델은 느리다"의 실제 원인. RL 정책은 보상 최대화로 최적화돼 군더더기가 없고, 그 "빠름"이 데이터에 담겨 증류된다.

(3) 데이터가 정책 자신의 상태 분포에서 나온다

사람 데모는 사람이 만든 상황만 담는다. RL 정책은 자기가 실제로 마주치는 상황(살짝 어긋난 위치, 미끄러진 순간)과 거기서 복구하는 방법을 함께 담는다.

비유

사내에 커넥터 조립만 만 번 해본 숙련공 3명(이더넷·VGA·USB)이 있다. 각자 자기 부품은 눈 감고도 꽂지만 다른 부품은 못 한다. 한편 공대 갓 졸업한 신입은 원리를 알고 처음 보는 부품도 시도는 하지만 손이 느리고 자주 실패한다.

RLDG: 숙련공들에게 밤새 작업시키며 전 과정을 녹화(2단계)하고, 그 영상으로 신입을 훈련시킨다(3단계). 신입은 숙련공의 손기술 + 자기 원래의 응용력을 둘 다 갖게 되어, 숙련공이 한 번도 안 만져본 부품까지 잘 꽂는다.

그리고 발견 하나 더 — 신입을 가르칠 때 선배(사람) 작업 영상보다 숙련공 로봇의 영상이 더 좋은 교재였다. 사람은 매번 조금씩 다르게 하고 중간중간 망설이지만, 로봇 숙련공은 늘 똑같이 군더더기 없이 하기 때문이다.

한계 → 장면 10으로

여기까지가 "스페셜리스트 → 제너럴리스트" 화살표다. 그런데 비대칭이 있다.

  • 제너럴리스트는 스페셜리스트 덕에 좋아진다 ✅
  • 그런데 다음 스페셜리스트를 학습시킬 때 좋아진 제너럴리스트가 전혀 도움을 못 준다 ❌

1단계의 RL은 여전히 맨땅에서 혼자 성공해야 한다. 좋은 파운데이션 모델을 옆에 두고도 안 쓴다. 이 비대칭이 장면 10의 문제 제기이고, 화살표를 되돌린 것이 RLT(장면 11).

장면 17 심화 — CFGRL: "좋은 데이터 쪽으로 줌인하기"

그림 읽는 법

세 개의 점 구름에서 점 하나 = 정책이 뽑아낼 수 있는 하나의 액션 후보.

  • 점의 위치 = 액션의 내용 (그리퍼를 어느 방향으로 얼마나 움직일지)
  • 점의 색 = 그 액션의 좋음 정도(어드밴티지). 노랑 = 나쁨, 보라 = 좋음
  • 점의 밀도 = 정책이 그 액션을 뽑을 확률

즉 "정책에게 '이 상황에서 뭐 할래?' 하고 1000번 물어봤을 때 나온 대답들의 분포". 이 문제에서는 오른쪽(보라)이 정답 영역, 왼쪽(노랑)이 실패 영역이다.

세 패널

① Unconditional — $\hat\pi(a|s)$ : "데이터에 있던 대로"

타원이 고르게 채워져 노랑도 보라도 골고루. 모아둔 데이터 전체를 통째로 BC한 결과 — 성공 액션도 실패 액션도 그대로 재현한다. 장면 15의 "(−) 대부분이 나쁜 데이터"를 그림으로 그린 것.

② Optimality Conditioned — $\hat\pi(a|s,o) \propto \hat\pi(a|s)\,p(o|s,a)$ : "좋은 쪽으로 해줘"

$o$는 "이 시도는 잘된 것인가?"라는 예/아니오 스위치. 학습 시 각 데이터에 라벨을 붙여 조건으로 넣어두면, 나중에 "$o$=잘된 것"으로 켜고 물어볼 수 있다.

오른쪽 보라가 약간 촘촘해졌지만 왼쪽 노랑도 여전히 남아 효과가 미지근하다. $p(o|s,a)$는 부드러운 확률이라, 좋은 영역 0.7 / 나쁜 영역 0.3이면 한 번 곱해도 비율이 2배 정도밖에 안 벌어진다. 방향은 맞는데 너무 약하다.

③ Optimality Guided — $\hat\pi(a|s)\,p(o|s,a)^w$ : "좋은 쪽으로 세게 해줘"

똑같은 확률에 지수 $w$(guidance weight) 를 씌운 것뿐인데 결과가 극적이다. 노랑은 거의 사라지고 점들이 오른쪽 보라 영역에 초승달 모양으로 몰린다. 이것이 "좋은 데이터의 모드로 줌인".

지수의 효과: 0.7 대 0.3은 2.3배지만, 5제곱하면 $0.7^5=0.17$ 대 $0.3^5=0.002$ 로 70배가 된다. 작은 선호도 차이를 큰 선호도 차이로 증폭시키는 손잡이가 $w$다.

패널한 문장$w$ 값
Unconditional데이터에 있던 그대로 (잘한 것 + 못한 것)$w = 0$
Optimality Conditioned"잘된 쪽으로" — 방향은 맞지만 약함$w = 1$
Optimality Guided"잘된 쪽으로 훨씬 세게" — 좋은 모드에 집중$w > 1$

세 그림이 전부 같은 모델 하나에서 나온다. 모델은 한 번만 학습했고, 뽑아 쓸 때 손잡이만 돌렸다.

왜 대단한가 — "학습이 아니라 추론 시점"

보통 RL에서는 "얼마나 공격적으로 개선할 것인가"($\beta$)를 학습 전에 정해야 하고, 잘못 잡으면 며칠치 학습을 날린다. CFGRL은 그 결정을 로봇을 돌리는 순간으로 미룬다. 논문 제목의 Controllable이 정확히 이 뜻 — 모델은 하나인데 상황에 따라 $w$로 보수적/공격적을 오갈 수 있다.

익숙한 손잡이

디퓨전 이미지 생성의 CFG scale과 완전히 같은 것이다. 차이는 조건이 "텍스트 프롬프트"가 아니라 "이 행동은 잘된 것" 이라는 점뿐.

학습 방법 — 랜덤 드롭아웃

학습 시 최적성 라벨 $o$를 무작위로 가끔 빼고 학습시키면 한 모델이 두 가지를 동시에 배운다.

  • 라벨을 줬을 때 → "잘된 것처럼 / 잘 안 된 것처럼" 행동 → $\hat\pi(a|s,o)$
  • 라벨을 뺐을 때 → 데이터 평균대로 행동 → $\hat\pi(a|s)$

이 둘의 차이 방향이 개선 방향이고, 샘플링 때 그 방향으로 $w$배 밀면 세 번째 패널이 나온다.

나쁜 데이터를 버리지 않는 이유

나쁜 데이터는 "이쪽은 아니다"라는 방향 정보로 쓰인다. 왼쪽 노랑을 알고 있어야 거기서 멀어질 줄 안다.

AWR보다 안정적인 이유

AWR은 각 데이터에 좋음 정도로 가중치를 주는데, 그 가중치가 지수함수라 좋은 소수를 뺀 나머지는 거의 0이 된다. 배치 256개 중 실질적으로 5~10개만 기여하면 유효 배치 크기가 10 근처가 되어 그래디언트가 요동친다.

CFGRL은 256개 전부를 쓴다. 좋은 것은 "$o$=참의 예시", 나쁜 것은 "$o$=거짓의 예시" — 역할만 다를 뿐 전부 학습 신호다.

주의점 — 슬라이드가 은근히 보여주는 것

세 번째 패널의 점들이 초승달 모양으로 데이터 영역 가장자리에 몰려 있고 가운데가 비었다. $w$를 계속 키우면 이 현상이 심해진다.

  • 다양성이 사라져 한 점으로 붕괴
  • 결국 원래 데이터에 없던 영역까지 밀려남 (out-of-distribution)

그러면 "이론상 최고 어드밴티지지만 실제로는 로봇이 부술 행동"이 나온다. 이미지 생성에서 CFG scale을 20까지 올리면 그림이 타버리는 것과 같은 현상 — $w$는 적당한 지점에서 조절해야 하는 손잡이다.

장면 18~19로 이어지는 고리

  • π\*0.6은 디퓨전 기반 VLA → CFG를 붙일 자리가 이미 있음
  • 어드밴티지 $A(o,a) = r_{t:N} + V(o_{t+N}) - V(o_t)$ 계산 후
  • 이진화 $\mathbb{1}[A > \epsilon]$ → 이것이 이 슬라이드의 $o$
  • 언어 지시와 나란히 조건으로 투입

즉 "espresso 만들어"라는 언어 조건과 "잘된 행동으로 해"라는 최적성 조건을 같은 방식으로 넣는다. 별도 actor 없이 파운데이션 모델 자체가 RL의 actor가 되는 것 — 장면 15에서 세운 목표가 여기서 달성된다.

"둘까지는 괜찮다"의 실제 사례

  • big model + sample-efficient RL (쉬운 과제) — LLM의 RLHF/파인튜닝. 큰 모델을 적은 샘플로 튜닝하지만 이미 아는 것을 배치하는 수준이라 새 전략 발명이 불필요
  • big model + hard task (샘플효율 포기) — 시뮬레이션 대규모 병렬 RL(게임 AI, sim-to-real 로코모션). 수십억 스텝이 가능하지만 장면 5 표 왼쪽의 "샌드박스만 배운다"에 걸림
  • sample-efficient RL + hard task (모델 크기 포기) — 장면 6~8의 RLPD/SERL 스페셜리스트. 실세계 1~2시간에 100% 성공률. 대신 사전학습이 없어 일반화가 없음

세 개가 겹치면 왜 무너지나

  • 샘플효율을 얻으려면 prior에 붙어 있어야 한다 (BC 정규화, off-policy, 작은 탐색 반경)
  • 그런데 hard task는 정의상 prior 밖으로 나가야 풀린다
  • 게다가 모델이 크면 밖으로 나가는 시도 몇 번에 모델 전체가 망가진다

발표 나머지 = 이 3중 결합을 쪼개는 우회로

기법완화하는 원

Q2. RLPD는 어떻게 작동하는가 (장면 6 상세)

원 논문: *Ball, Smith, Kostrikov, Levine, Efficient Online Reinforcement Learning with Offline Data, ICML 2023. 이름은 Reinforcement Learning with Prior D*ata. 관련 노트: [[clippings/yt_30_RLPD with Isaac Sim.md]]

출발점: off-policy actor-critic (SAC)

RLPD는 새 알고리즘이라기보다 SAC에 붙인 다섯 개의 설계 선택에 가깝다.

부품역할비유
Actor $\pi(a\s)$상태를 보고 행동을 뱉는 정책실제로 손을 움직이는 사람
Critic $Q(s,a)$"이 상태에서 이 행동을 하면 앞으로 총 얼마나 좋을까"옆에서 채점하는 코치
Replay buffer겪은 모든 (s, a, r, s')를 저장연습 일지

여기서 off-policy가 결정적이다. 버퍼의 경험이 지금의 정책이 만든 것일 필요가 없다 — 옛 정책이든, 사람이 만든 것이든, 엉망인 것이든 전부 학습에 쓸 수 있다. (PPO 같은 on-policy는 불가능) 이 성질이 RLPD 전체의 열쇠다.

문제 1 — 그냥 SAC를 실세계에 돌리면

희소 보상 과제에서 초기 정책은 무작위로 팔을 흔든다. 무작위로 USB가 꽂힐 확률은 사실상 0. 보상을 못 받으면 critic이 배울 게 없고, critic이 없으면 actor도 방향을 못 잡는다 → 영원히 제자리.

문제 2 — 그럼 데모로 사전학습(offline RL)부터 하면?

(a) 분포 이동과 Q값 폭주 — critic은 $Q(s', \pi(s'))$를 참조하는데, $\pi(s')$가 데이터에 없던 행동을 제안하면 신경망이 그 지점을 아무렇게나 외삽하고 보통 과대평가로 간다. 그리고 이건 자기 강화 루프다.

critic이 본 적 없는 행동 a*의 Q값을 과대평가
  → actor가 "a*가 최고네" 하고 그쪽으로 이동
  → 과대평가된 값이 벨만 백업으로 이전 상태에 전파
  → 전체 Q함수가 부풀어 오름 → 발산

(b) 보수화가 온라인 전환에서 발목을 잡는다 — 보수적으로 사전학습한 정책은 데모 근처에 묶인다. 온라인으로 넘어가면 데모를 넘어서질 못하거나, 족쇄를 풀면 초반에 급락(unlearning)한다. 실세계 로봇에서 초반 급락은 시간 낭비이자 하드웨어 파손이다.

RLPD의 답: 사전학습 단계를 아예 없앤다

> 오프라인 사전학습도, 명시적 보수화도 하지 마라. 처음부터 온라인 RL을 돌리되, 매 배치의 절반을 데모에서 뽑아라.

정책은 랜덤 초기화로 시작한다. 별도 offline 단계가 없으니 (b)의 전환 충격이 원천적으로 없다. 대신 (a)의 Q값 폭주를 명시적 페널티가 아니라 아키텍처로 막는다.

다섯 개의 재료

① Symmetric sampling — 배치의 50:50 고정 오프라인 버퍼(사람 데모, 고정)와 온라인 버퍼(자율 수집, 증가)를 따로 두고, 배치 256개 중 항상 128개는 오프라인, 128개는 온라인에서 뽑는다.

"그냥 데모를 버퍼에 부어넣기"(DDPGfD)와의 차이

데모 50개를 버퍼에 넣고 온라인 경험이 5만 개 쌓이면 데모가 뽑힐 확률은 0.1%로 희석된다. 정작 정교한 마무리를 다듬어야 할 학습 후반에 데모의 영향력이 사라지는 것. Symmetric sampling은 비율을 영원히 50%로 고정한다.

② Critic에 LayerNorm — 사실상 제일 중요한 트릭 어블레이션에서 이것만 빼도 많은 태스크가 발산한다. LayerNorm이 없으면 은닉 특징 벡터의 크기에 제한이 없어, 데이터에서 먼 행동일수록 특징이 커지고 Q값이 얼마든지 커질 수 있다. LayerNorm은 특징 크기를 묶어 Q값이 "본 적 있는 값 범위"를 크게 벗어나지 못하게 한다. CQL처럼 OOD에 벌점을 준다고 말하지 않고도, 구조 자체가 병적 낙관을 불가능하게 만드는 공짜 암묵적 보수화.

③ Critic 앙상블 + 랜덤 부분집합 최소값 Critic을 10개 독립 학습시키고, 타깃 계산 시 무작위 2개를 뽑아 더 작은 값을 쓴다(REDQ 방식). 하나가 과대평가해도 min에서 걸러진다. "무작위 2개"인 이유는 전체 10개의 min을 쓰면 너무 비관적이 되어 학습이 멈추기 때문 — 비관의 강도를 조절하는 노브다.

④ 높은 UTD ratio — 샘플효율의 직접적 원천 UTD(Update-To-Data) = 환경 스텝 1회당 그래디언트 업데이트 횟수. 보통 SAC는 1, RLPD는 20. 실세계에서 비싼 것은 로봇의 시간이지 GPU 시간이 아니므로 같은 경험을 20배 더 짜낸다. 이것이 "1~2시간 학습"의 정체. 단, UTD를 올리면 적은 데이터에 20배 과적합하므로 ②·③이 반드시 함께 필요하다 — 이 넷은 세트다.

⑤ SAC의 엔트로피 최대화 유지 정책이 너무 빨리 결정론적으로 굳는 것을 막아 탐색을 유지한다.

전체 루프

offline_buffer = load_demos()        # 사람 데모 20~50개
online_buffer  = []                  # 비어 있음
actor, critics = random_init()       # 사전학습 없음!

for step in range(N):
    # --- 환경과 상호작용 (실세계 1스텝) ---
    a = actor.sample(s)
    s2, r, done = env.step(a)        # r = 이진 분류기가 준 0/1
    online_buffer.append((s, a, r, s2))

    # --- UTD=20: 스텝 1회당 20번 업데이트 ---
    for _ in range(20):
        batch = concat(
            offline_buffer.sample(128),   # 50%
            online_buffer.sample(128),    # 50%
        )
        i, j = random_pick_two(critics)              # 앙상블 중 2개
        target = r + γ * min(Q_i(s2, a2), Q_j(s2, a2))
        update_all_critics(batch, target)            # LayerNorm 들어간 critic
        update_actor(batch)

실세계 로봇에 얹을 때 (장면 6~8)

발표에서 강조된 건 알고리즘 자체가 아니라 주변부를 얼마나 단순화했느냐다.

요소선택왜
관측손목 카메라 + 사전학습 비전 인코더(고정)픽셀부터 RL로 배우면 샘플효율이 무너짐. 인코더는 얼리고 위의 작은 정책만 학습
보상이진 이미지 분류기 (성공/실패)reward shaping 지옥을 회피. 성공 사진 수십 장으로 분류기 하나면 끝
인간 개입조이스틱으로 언제든 끼어들어 교정 시연off-policy라서 공짜. 교정 궤적을 버퍼에 던져 넣으면 됨. on-policy면 불가능

세 번째가 특히 우아하다 — 탐색 문제를 사람이 대신 풀어주는 것이고, 이 버전이 HIL-SERL이다. 100% 성공률은 대개 이 개입이 있는 설정에서 나온다.

파인만식 설명

  • RLPD 전체 — 신입 요리사에게 선배의 시범 영상을 계속 반복 재생해 두면서 동시에 직접 계속 썰어보게 한다. 핵심은 끝까지 반반이라는 것 — 본인 연습이 쌓였다고 시범 영상을 안 보게 두면 후반의 미세한 손목 각도를 영영 못 배운다.
  • LayerNorm — 코치에게 "점수는 0~10점 사이로만 매겨라"는 규칙을 주는 것. 없으면 코치가 본 적 없는 괴상한 동작에 "100만 점!"이라 우기고 신입이 그 헛소리를 좇는다.
  • 앙상블 + min — 코치를 10명 앉혀 놓고 매번 무작위 2명에게 물어 더 짠 점수를 채택.
  • 높은 UTD — 연습 한 번 하고 비디오를 20번 돌려보며 복기. 몸을 움직이는 건 느리지만 복기는 값싸니까.
  • 인간 개입 — 막힐 때 선배가 손을 얹어 한 번 해주면, 그 순간이 그대로 시범 영상에 추가된다.

왜 이걸 큰 모델엔 못 쓰나 (→ 장면 5로 회귀)

RLPD는 sample-efficient RL + hard task를 실세계에서 성립시킨 성공 사례지만 big model을 못 넣는다.

  • UTD=20을 40억 파라미터 VLA에 = 계산량 감당 불가
  • Critic 앙상블 10개를 VLA 크기로 = 더더욱 불가
  • 애초에 사전학습이 없어 일반화의 기반 자체가 없음

그래서 발표는 여기서 증류(RLDG)와 RL 토큰(RLT) 두 갈래로 갈라진다.

왜 질문거리가 되는가 — RL 데이터의 성질

RL이 만드는 데이터는 "학습 과정 전체의 기록"이다. 2시간 학습의 궤적 분포는 대략:

시기궤적의 모습비중
초반거의 무작위, 구멍 근처도 못 감많음
중반가끔 성공, 자주 미끄러지고 재시도가장 많음
후반빠르고 정확하게 성공적음

즉 수집 데이터의 절대다수는 최종 정책이 만든 것이 아니다. 이건 결함이 아니라 RL의 정의다.

두 선택지와 대가

선택지 A — 최종 정책의 롤아웃만 사용

  • (+) 전부 좋은 데이터라 그냥 BC로 충분하다. 가치함수도 advantage도, RL 기계장치가 전혀 필요 없다
  • (−) "most data RL collects not from this policy" — 2시간 굴려 마지막 몇 분어치만 씀. 실세계 로봇 시간이 가장 비싼 자원인데 대부분을 버린다

→ 실제로 RLDG(장면 9)가 이 방식이다.

선택지 B — RL 중 수집한 전부 사용

  • (+) 데이터를 다 쓴다 (양이 수십 배)
  • (−) "most of the data is bad" — 그리고 BC는 나쁜 데이터를 걸러낼 능력이 없다. BC의 목적함수는 "데이터에 있는 행동의 확률을 높여라"이므로 실패 궤적을 넣으면 실패하는 법을 성실히 배운다. BC 정책의 성능 상한은 데이터의 평균 품질이다

그런데 "나쁜 데이터"가 아까운 두 가지 이유

① 실수와 복구 궤적 → 회복력 BC의 고질병은 복합 오차(compounding error)다. 사람 데모는 깔끔한 성공 궤적뿐이라 정책이 "실수한 상태"를 본 적이 없다. 한 번 미끄러지면 분포 밖으로 나가 무너진다. RL 로그에는 미끄러지고 → 다시 잡고 → 성공하는 궤적이 가득하다. 장면 8의 "교란해도 복구", 장면 19의 "셔츠를 구겼다가 다시 펴기"가 이 데이터에서 나온다.

② 실패도 정보다 "이 각도로 밀면 안 꽂힌다"는 정답이 어디 없는지를 알려준다. BC는 쓸 방법이 없지만 가치를 아는 알고리즘은 쓸 수 있다.

그래서 원하는 것

> 좋은 데이터와 나쁜 데이터를 섞어서 학습할 수 있다면, 별도 actor 없이 로봇 파운데이션 모델 자체를 RL의 actor로 쓸 수 있다.

기법RL을 수행하는 주체VLA의 역할
RLDG (장면 9)작은 스페셜리스트나중에 받아먹는 학생
RLT (장면 11)작은 RL actor/critic표현을 빌려주는 조언자
여기서 원하는 것VLA 자신주인공

VLA가 혼합 품질 데이터로 직접 개선된다면 작은 정책을 따로 학습시키고 증류하는 단계가 통째로 사라진다. 장면 5의 벤 다이어그램에서 끝내 못 넣었던 big model 원을 안으로 들여놓는 길이고, 이미 모아둔 데이터로 하는 offline RL이므로 sample-efficient RL 요구도 함께 느슨해진다.

남은 문제 — "이미 offline RL 기법 있잖아?"

AWR(advantage-weighted regression): advantage에 비례한 가중치를 주고 BC. 그런데 장면 17에서 지적하듯 AWR은 배치의 다수 샘플에 사실상 가중치 0을 준다 — 나쁜 데이터를 "쓰는 척하며 버리는" 것이라 선택지 A의 낭비로 되돌아가고, 유효 배치 크기가 쪼그라들어 불안정하다.

→ 필요한 것: 나쁜 데이터를 버리지 않으면서 좋은 쪽으로 정책을 미는 방법. 그것이 장면 16의 CFGRL이다. 모든 샘플을 그대로 학습에 쓰되 "잘된 것/안 된 것" 라벨만 붙이고, 개선은 학습이 아니라 추론(샘플링) 시점에 일어나게 한다.

파인만식 설명

시험 공부에 비유하면,

  • 선택지 A = 만점 답안지 3장만 보고 공부. 깨끗하지만 양이 없고 틀리는 방식을 배우지 못해 함정 문제에 무너진다
  • 선택지 B + BC = 100장을 다 보되 점수를 안 보고 통째로 외움. 틀린 풀이까지 그대로 익힌다
  • 원하는 것 = 100장을 다 보되 각 장에 점수를 라벨로 붙여서 본다. 틀린 답안도 "이 길로 가면 막힌다"는 지도가 되므로 버리지 않는다

그리고 "별도 actor 없이"는, 지금까지 과외 선생(작은 RL 정책)이 대신 공부하고 요약노트를 넘겨주던 방식을 그만두고 학생이 직접 100장을 보고 스스로 실력을 올리게 하자는 이야기다.

Q1. SERL은 어떤 건가?

한 줄 정의

SERL = Sample-Efficient Robotic reinforcement Learning. "실제 로봇이 실제 작업장에서, 몇 십 분~몇 시간 만에 강화학습으로 정밀 조작을 습득"하게 만드는 오픈소스 소프트웨어 묶음.

중요한 오해 방지: SERL은 새로운 RL 알고리즘이 아니다. 장면 6에서 Levine이 "알고리즘이 뭔지는 별로 중요하지 않다"고 한 그대로, SERL은 실세계 로봇 RL을 실제로 돌아가게 만드는 엔지니어링 부품 세트다.

Q2. 장면 16(CFGRL)의 수식은 무엇을 말하는가

발표에서 유일한 수식 슬라이드이자 지적 클라이맥스. 장면 16·17이 한 세트다.

출발점 — 장면 15의 딜레마

RL로 데이터가 잔뜩 쌓였는데 파운데이션 모델에 어떻게 넣나?

선택지장점치명적 단점
최종 정책 데이터만전부 좋은 데이터, BC로 충분RL이 모은 데이터의 대부분을 버림
RL 중 전체 데이터양 많음, 실수·복구 포함 → 강건대부분이 나쁜 데이터

> 질문: 좋은 데이터와 나쁜 데이터를 섞어서, 나쁜 건 안 배우면서 학습할 수 없을까? > 그게 되면 별도 actor 없이 로봇 파운데이션 모델 자체를 RL의 actor로 쓸 수 있다.

사전지식 ① — classifier-free guidance(CFG)

Stable Diffusion의 "CFG scale 7.5" 슬라이더가 바로 이것.

  • 학습: 캡션을 붙여 학습하되 가끔 캡션을 무작위로 지움(dropout 10~20%) → 하나의 모델이 조건부 $p(x|c)$와 무조건부 $p(x)$를 동시에 학습
  • 생성: 두 예측의 차이 방향으로 더 밀어붙임

$$\nabla\log\tilde p = \nabla\log p(x) + w\big[\nabla\log p(x|c) - \nabla\log p(x)\big]$$

대괄호 안이 "고양이스러움의 방향". $w$를 키우면 더 전형적인 고양이가 나온다.

이름의 유래가 중요하다

"classifier-free" = 별도 분류기를 학습하지 않는다. 조건부와 무조건부의 차이가 이미 분류기 역할을 하기 때문. 그리고 CFG는 학습 알고리즘이 아니라 추론(샘플링) 시점 기법이다.

사전지식 ② — KL 정규화 RL 목적함수 (슬라이드 수식 1)

$$J(\pi_\theta) = \underbrace{\mathbb{E}_{\tau \sim p(\tau|\pi_\theta)}\Big[\sum_t \gamma^t r(s_t, a_t)\Big]}_{\text{① 보상을 최대화하라}} - \beta\,\underbrace{\mathbb{E}_{s}\Big[D_{\mathrm{KL}}\big(\pi_\theta(a|s)\,\|\,\hat{\pi}(a|s)\big)\Big]}_{\text{② 단, 참조 정책에서 너무 멀어지지 마라}}$$

슬라이드의 두 화살표:

  • $\pi_\theta$ ← *"policy that matches the good data"*
  • $\hat\pi$ ← *"policy that matches all the data"*

$\beta$가 크면 고삐를 꽉 쥠(개선 폭 작고 안전), 작으면 공격적 개선(위험). 이 형태는 RLHF의 PPO와 정규화된 offline RL이 공유하는 공통 골격이다.

수식 2 — 정답의 형태

$$\pi(a|s) \propto \hat{\pi}(a|s)\,\exp\big(A(s,a)\big)^{1/\beta}$$

> 정답 정책 = (전체 데이터 정책) × (그 행동이 얼마나 좋았는지의 지수)

원래 분포를 그대로 두되 좋았던 행동 쪽을 부풀리고 나빴던 쪽을 짓눌러 분포를 기울인 것. 문제는 — 이 곱셈 분포에서 실제로 샘플링하는 게 어렵다(기존 AWR·IQL·DDPG+BC는 다들 이걸 근사하려 애쓴다).

수식 3 — 마법의 트릭: $\exp(A)$를 "확률"이라 부르기

$$p(o|s,a) = \frac{f(A(s,a))}{Z(s)}, \qquad \pi(a|s) \propto \hat{\pi}(a|s)\,p(o|s,a)$$

$\exp(A)$는 그냥 양수 → $Z(s)$로 정규화하면 확률로 해석 가능. 그래서 가상의 이진 변수 $o$(optimality)를 발명한다: $o=1 \iff$ "이 행동은 좋았다".

그런데 $\hat\pi(a|s)p(o|s,a)$는 베이즈 정리 그 자체:

$$\hat\pi(a|s,o) = \frac{\hat\pi(a|s)\,p(o|s,a)}{p(o|s)} \;\propto\; \hat\pi(a|s)\,p(o|s,a)$$

핵심 통찰

"KL 정규화 RL의 최적 정책" = "전체 데이터로 학습한 정책을, '이건 좋은 행동이야($o$=참)'라는 조건으로 조건화한 것" → RL의 정책 개선이 조건부 생성(conditional generation)과 수학적으로 같은 것이었다.

스코어 함수로 옮기면 → CFG와 동형

$$\nabla_a\log\pi(a|s) = \nabla_a\log\hat{\pi}(a|s) + \nabla_a\log p(o|s,a)$$

여기에 개선 강도 $w$를 붙이면 $\pi_w(a|s) \propto \hat{\pi}(a|s)\,p(o|s,a)^{w}$이고, 이는 CFG 공식과 글자까지 일치한다($\nabla\log\hat\pi(a|s,o) - \nabla\log\hat\pi(a|s) = \nabla\log p(o|s,a)$이므로).

수식 2와 비교하면 결정적 대응 관계:

$$\boxed{\;w = 1/\beta\;}$$

가장 중요한 한 문장

이미지 생성에서 "고양이스러움을 얼마나 세게 밀지" 정하던 guidance weight $w$가, RL에서는 "정책을 얼마나 공격적으로 개선할지" 정하는 노브와 완전히 같다.

  • $w=0$ → 원본 분포 그대로 (개선 없음 = BC)
  • $w=1$ → 정직한 베이즈 조건화 (표준 1스텝 정책 개선)
  • $w=3,5,\dots$ → 좋은 데이터 쪽으로 과장해 밀어붙임

논문 제목의 "Controllable"이 여기서 나온다.

장면 17의 세 점구름 = 위 세 단계 (노랑=나쁨, 보라=좋음)

그림수식보이는 것
Unconditional$\hat\pi(a\s)$노랑~보라가 골고루 퍼진 타원
Optimality Conditioned$\hat\pi(a\s)p(o\s,a)$보라 밀도가 살짝 높아짐 ($w=1$)
Optimality Guided$\hat\pi(a\s)p(o\s,a)^{w}$보라 영역에 초승달로 몰림, 노랑 거의 소멸 ($w>1$)

실제 알고리즘 — 놀랄 만큼 간단

[학습]
1. 모든 데이터(좋은 것 + 나쁜 것)를 모은다
2. 이진 라벨을 붙인다:  o = 1[A(s,a) > ε]
3. 디퓨전 정책을 o 조건으로 평범하게 지도학습
   단, 학습 중 o를 랜덤 드롭아웃 (CFG 표준 레시피)

[추론]
4. o=1로 조건화하되 guidance weight w로 증폭

주목할 점 세 가지:

  1. 별도 actor 네트워크가 없다. 정책 자체가 디퓨전 모델이고 개선은 샘플링 시점에 일어난다.
  2. 디퓨전 샘플링 체인을 통과하는 역전파가 없다. 거대 VLA를 policy gradient로 밀면 샘플링 전 과정을 미분해야 해서 비용·불안정성이 감당 안 되는데, CFGRL은 지도학습 + 샘플링 트릭뿐이다.
  3. $w$는 배포 시점 다이얼이다. 기존 offline RL은 $\beta$를 바꾸려면 재학습해야 했다.

AWR보다 안정적인 이유 — 데이터를 안 버린다

$$\mathcal{L}_{\text{AWR}} = \mathbb{E}\big[\exp(A(s,a)/\beta)\cdot \log\pi_\theta(a|s)\big]$$

  • AWR: 어드밴티지 낮은 샘플은 가중치 ≈ 0 → 배치 256개 중 실질 10여 개만 기여 → 실효 배치 붕괴, 분산 폭증
  • CFGRL: 모든 샘플이 가중치 1로 들어간다. 나쁜 샘플은 "$o=0$의 예시"라는 정당한 학습 신호
  • 나쁜 데이터가 있어야 무조건부 모델 $\hat\pi(a|s)$가 제대로 학습되고, 그래야 [조건부 − 무조건부] 차이(= 개선 방향)가 정확해진다
  • 실패 데이터는 "버리는 것"이 아니라 "방향을 정의하는 것"

왜 로봇에 결정적인가 — 장면 18로 이어지는 다리

> *π0, π\0.6 같은 로봇 파운데이션 모델은 이미 디퓨전(플로우) 기반이다.**

새 아키텍처가 필요 없다. 조건 입력 하나(어드밴티지 이진 라벨)를 추가하고 샘플링 때 guidance를 켜면 끝. 장면 19의 π\*0.6이 하는 일이 정확히 이것:

$$A(o,a) = r_{t:N} + V(o_{t+N}) - V(o_t) \;\longrightarrow\; \mathbb{1}[A(o,a) > \epsilon] \;\longrightarrow\; \text{정책의 조건 입력}$$

언어 지시를 조건으로 넣던 그 자리에 어드밴티지 라벨을 하나 더 끼워 넣는 것. 결과가 장면 20의 4개 과제 중 3개 처리량 2배다. 그리고 장면 15의 딜레마가 해소되면서 로봇 파운데이션 모델 자체가 RL의 actor가 된다.

비유

> CFGRL = 요리 학원의 "잘된 예 / 잘못된 예" 학습법 > > 잘 만든 김밥 사진 500장과 망친 김밥 사진 500장을 전부 보여주며 "합격"/"불합격" 스티커를 붙인다. 망친 사진을 버리지 않는 게 핵심 — 두 무더기의 차이가 곧 "합격의 방향"을 정의하기 때문. > > 실제로 말 때는 주문만 바꾼다: "평소대로"($w{=}0$) / "합격 쪽으로"($w{=}1$) / "합격 쪽으로 훨씬 세게"($w{=}3$). 학원을 다시 다닐 필요가 없다 — 이것이 추론 시점 정책 개선.

B. 장면 11 심화 — RLT는 왜 작동하는가

핵심 타협안

큰 모델을 직접 RL로 학습하면 장면 5의 3중 결합에 정면으로 걸린다. 그래서 우회한다.

  • 40억짜리 VLA는 얼려둔다(frozen) → 망가질 일이 없음
  • 실제 학습되는 건 아주 작은 RL actor & critic → 샘플효율 확보
  • 대신 작은 RL이 큰 모델의 지식을 읽을 통로를 뚫어준다 ← 이것이 RL 토큰

왜 1×2048로 압축하나

VLA 내부 표현은 N × 2048로 너무 커서, 15분치 데이터로 학습하는 작은 네트워크에 그대로 먹이면 과적합·발산한다. 그래서 토큰 딱 1개로 쥐어짠다.

정보 손실이 없음을 보장하는 장치가 오토인코더 구조다. 디코더가 그 1개 토큰만 보고 원래 N × 2048을 복원하도록 함께 학습시킨다 — 복원이 되면 그 안에 정보가 다 들어있다는 뜻.

`e_r,1`의 정체

인코더 왼쪽에 붙은 입력은 학습 가능한 질의 토큰이다. BERT의 [CLS]처럼 "이 슬롯이 전체 정보를 빨아들여라" 라고 지정한 빈 그릇으로, cross-attention이 N개 토큰을 훑어 이 하나에 요약한다.

읽는 법: 인식(RL 토큰)이 압도적으로 중요하고, 행동 힌트(pass-through)는 가속 장치, BC 정규화와 청킹은 없으면 아예 안 되는 필수 조건.

본질은 탐색(exploration) 문제 해결

[일반 RL] 랜덤 액션 → 실패 → 랜덤 → 실패 … (보상 신호를 아예 못 봄)
[RLT]     VLA의 "그럭저럭 되는" 액션 근처에서 탐색 → 가끔 성공 → 신호 확보 → 개선

즉 0→100이 아니라 70→100 문제로 바꾼 것. Q&A(29:38)에서 Levine이 직접 확인한 관점 — "제너럴리스트는 탐색을 위한 훌륭한 행동 사전확률". 심화 해설 ③의 HIL-SERL 계보(사람이 prior를 주입해 탐색을 돕는다)에서 사람 자리에 파운데이션 모델을 앉힌 것이다.

동작 단계별로 보면:

  • 초반 (critic이 아직 무지) → BC 항이 지배 → VLA를 흉내내며 안전하게 데이터 수집
  • 후반 (critic이 "여긴 이렇게 하면 더 빠르다"를 학습) → BC를 거스르는 게 이득인 지점에서만 벗어남
RLT 스페셜리스트는 독립 모델이 아니다

SERL/RLPD 스페셜리스트(장면 6~8)는 작은 네트워크 하나로 완결되지만, RLT 산출물은 추론할 때도 VLA가 RL 토큰과 액션 청크를 계속 공급해줘야 동작한다. 독립 모델이 아니라 VLA에 덧붙인 어댑터에 가깝다.

C. 장면 18~19 심화 — π\*0.6: advantage를 "언어처럼" 조건으로 넣기

핵심 아이디어 한 줄

> 모든 데이터에 잘한 행동 / 못한 행동 딱지를 붙여 통째로 학습시키고, 실행할 때는 잘한 행동 딱지를 요청한다.

기존 VLA:  [이미지] + ["커피를 탬핑해라"]                  → 액션
π*0.6:     [이미지] + ["커피를 탬핑해라"] + [👍 좋은 행동]  → 액션
                                            └─ advantage 조건

새로운 RL 알고리즘도, 별도 actor 네트워크도 필요 없다. VLA가 이미 할 줄 아는 "조건화"에 슬롯 하나를 더 얹었을 뿐이다. 슬라이드 제목 "Conditioning as policy extraction at scale" 이 정확히 이 뜻 — 원래 offline RL에서 가치함수로부터 정책을 뽑아내려면 AWR 같은 별도 알고리즘이 필요한데, 여기선 조건으로 넣기만 하면 된다.

학습과 추론의 비대칭 (핵심 마법)

조건에 넣는 값효과
학습 시데이터에 실제로 붙어 있던 딱지 (👍/👎 그대로)데이터를 하나도 안 버림
추론 시무조건 👍모델이 좋은 행동 쪽으로 이동
분간 단위는 에피소드가 아니라 **순간**이다

❌ "이번 빨래 개기는 성공/실패" ← 이건 그냥 성공률 ✅ "3분 12초 시점의 이 팔 동작이 상황을 개선했나, 악화시켰나"

$A(o,a) = r_{t:N} + V(o_{t+N}) - V(o_t)$ 가 재는 것이 바로 "직전보다 좋아졌나". 따라서 실패 에피소드 안의 잘한 구간에는 👍, 성공 에피소드 안의 삽질 구간에는 👎 가 붙는다. 궤적을 통째로 취하거나 버리는 게 아니라 잘게 썰어 구간별로 채점하는 것 — 이것이 "데이터를 안 버린다"의 실제 의미다.

왜 이진화(binarization)하나

실세계 가치함수 추정치는 노이즈가 심해 A = 0.37 같은 정밀값은 못 믿지만, "확실히 평균 이상" 정도는 신뢰할 만하다. 게다가 참/거짓 하나는 토큰 1개로 표현하기 딱 좋다.

데이터는 남이 준 게 아니라 자기 경험

π0.6 → 로봇에 올려 실제로 굴림 → 성공·실패·복구 전부 기록 (Autonomous Data)
     → 가치함수로 순간마다 👍/👎 → 그 데이터로 자기 재학습
     → π*0.6 → 다시 굴림 → 더 나은 데이터 → 반복

D. 장면 21 심화 — π0.7: "모델"이 아니라 "데이터"를 모은 것

가장 흔한 오해

❌ π0.7 = [나사 스페셜리스트] + [지퍼타이 스페셜리스트] + … 를 한 껍데기에 담아 상황에 맞게 골라 쓰는 것 (MoE/앙상블)

스페셜리스트는 부품이 아니라 데이터 공장이다. 모델을 모아둔 것이라면 새 과제엔 여전히 무력하지만, 데이터로 녹여 하나로 학습하면 일반화가 생긴다 — 장면 9 RLDG에서 이미 증명된 성질이다.

G. π0.7이 기존 VLA와 갈리는 4가지 축

기존 π0.5·π0.6도 웹 데이터는 썼다. 정확한 대비축은 "로봇이 어떻게 움직여야 하는가"의 정보원이 사람 데모뿐이었다는 점이다.

  1. 확장성 — 데이터가 사람 시간에서 로봇 시간으로. 사람 1명 × 1시간 = 1시간치(선형·비쌈·야간 불가) vs 로봇 10대 × 24시간 = 240시간치(병렬·저렴·무중단)
  2. 품질 상한 돌파 ⭐ — 사람 데모만으로는 절대 사람보다 잘할 수 없다(상한이 데이터에 박혀 있음). 장면 14의 RLT 66 vs Teleop 146처럼 사람보다 빠른 데이터가 존재해야 사람보다 빠른 모델이 나온다
  3. 데이터 종류의 우수성 — 장면 9: RL 데이터가 같은 개수의 성공 데모보다 효과적. RL 정책은 마르코프 정책이라 오직 현재 상태로만 결정하므로, 기억에 의존해 매번 다르게 움직이는 사람 데모보다 학습하기 깨끗하다
  4. 흡수 가능성 — 위 E절. 1~3이 아무리 좋아도 4가 없으면 못 쓴다

I. 파인만식 설명 (추가분)

  • RLT — 신입에게 무작정 "알아서 해보라" 하지 않고, 베테랑을 옆에 앉혀 "지금 상황은 이렇고, 나라면 이렇게 하겠다" 를 계속 알려준다. 신입은 모를 땐 따라가고, 자기가 더 나은 방법을 찾았을 때만 벗어난다.
  • *π\0.6 = 별점 달린 요리 영상으로 배우는 요리사* — 망한 영상도 버리지 않고 별 1개 딱지를 붙여 전부 본다. 실패를 봐야 "이러면 안 되는구나" 와 "망했을 때 이렇게 수습하는구나" 를 배우니까. 실제 요리할 땐 "별 5개짜리로" 라고 주문한다. 옆에는 "지금 잘 되고 있나"* 를 실시간으로 알려주는 게이지(가치함수) 가 달려 있어, 셔츠를 구겨버린 순간 바늘이 뚝 떨어지는 게 보인다.
  • π0.7 = 각 분야 장인들을 한 명에게 전수시킨 종합 셰프 — 칼질 장인·불 조절 장인·플레이팅 장인이 각자 수천 번 연습한 기록을 한 사람이 물려받는다. 배울 땐 각 기록에 "이건 4점, 이건 2점, 이건 3분 걸림" 꼬리표를 달아 익히고, 실전에선 "5점짜리로, 최대한 빠르게" 라고 스스로 주문한다. 장인들 본인은 전수가 끝나면 없어도 된다.
