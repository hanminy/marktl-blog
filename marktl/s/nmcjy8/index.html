PART 0

강화학습이란 무엇인가 — 지도학습과의 두 가지 차이

지도학습 (supervised learning)

우리가 이미 아는 것. (입력, 정답) 쌍이 주어진다.

사진 → "고양이"
사진 → "개"

모델은 입력을 보고 정답을 맞히도록 학습한다. 정답이 무엇인지 누군가 알려준다.

로봇에 적용하면 이것이 모방학습(imitation learning) 또는 행동 복제(behavior cloning, BC)다.

(카메라 화면, "커피 만들어") → 사람이 그 순간 취한 행동

강화학습 (reinforcement learning, RL)

두 가지가 다르다. 이 둘이 RL의 모든 어려움의 원천이다.

차이 ①: 정답이 없고 점수만 있다

“이 상황에서 무엇이 정답인가”를 아무도 모른다. 대신 행동을 하고 나면 점수(보상)가 온다.

지도학습:  이 상황에서는 왼쪽으로 3cm 움직이는 게 정답이야
강화학습:  (움직여봐) … 음, 7점.
           (다르게 움직여봐) … 이번엔 2점.

정답을 배우는 게 아니라, 점수를 높이는 방법을 스스로 찾아야 한다.

차이 ②: 내 행동이 다음에 볼 데이터를 바꾼다

지도학습에서 데이터셋은 고정이다. 내가 무엇을 예측하든 다음 사진은 그대로 온다.

RL에서는 내가 지금 한 행동이 다음 상황을 결정한다. 커피잔을 쏟으면, 그 다음부터 보는 화면은 “쏟은 상태”다. 데이터 분포가 내 정책에 의존한다.

IMPORTANT · 차이 ②가 왜 결정적인가

이것이 지도학습의 모든 이론이 RL에서 깨지는 이유다. 지도학습은 “학습 데이터와 테스트 데이터가 같은 분포”를 가정하는데, RL에서는 정책이 바뀌면 데이터 분포도 바뀐다. PART 5의 on-policy/off-policy 구분, PART 10의 covariate shift가 모두 여기서 나온다.

두 발표의 출발점

Levine 발표 장면 4의 핵심 주장이 정확히 이 대비다.

담당결과
지도학습 (pre-training)지식, 일반화, 언어 이해많은 것을 “그럭저럭”
강화학습 (post-training)특정 과제의 숙달, 속도그 과제를 “완벽하고 빠르게”

대체재가 아니라 상보재다. 지도학습만으로는 40%에서 멈추고(Finn 발표), RL만으로는 일반화가 없다(Levine 발표 장면 8의 스페셜리스트 한계).

PART 1

기본 어휘 — MDP

RL의 문제 설정을 MDP(Markov Decision Process, 마르코프 결정 과정)라 부른다. 다섯 개의 부품이 있다.

상태 s (state) / 관측 o (observation)

지금 세계가 어떤 상태인지. 로봇에서는 보통:

  • 관측 o: 카메라 이미지, 관절 각도(고유수용성 상태, proprioception)
  • 상태 s: 세계의 진짜 완전한 상태

카메라로는 세계를 다 볼 수 없으므로(가림, 시야 밖) 로봇 문제는 엄밀히는 POMDP(부분 관측 MDP)다. 논문들이 s와 o를 섞어 쓰는 이유이고, Finn 발표에서 가치함수 입력을 o로 쓴 이유이기도 하다.

실용적으로는 s ≈ o로 읽어도 대부분 문제없다.

행동 a (action)

로봇이 하는 것. 보통 연속값 벡터다.

a = [관절1 각도 변화, 관절2 각도 변화, …, 그리퍼 열림/닫힘]

예: 7자유도 팔 + 그리퍼 → a ∈ ℝ⁸

보상 r (reward)

행동 후 받는 점수. 두 종류가 있고 이 구분이 매우 중요하다.

종류뜻예
희소 보상 (sparse)성공하면 1, 아니면 0“에스프레소가 완성됐나?”
밀집 보상 (dense)매 스텝 세밀한 점수“포터필터와 그룹헤드의 거리에 반비례”

두 발표 모두 희소 보상을 쓴다. 이유는 밀집 보상을 손으로 설계하는 비용이 크고, 잘못 설계하면 로봇이 보상만 챙기고 과제는 안 하는 보상 해킹(reward hacking)이 생기기 때문이다.

  • Levine 장면 6 (RLPD): “이진 이미지 분류기가 주는 희소 보상”
  • Finn 00:25:00 (EXPO-FT): “규칙 기반 분류기의 sparse binary 신호”

WARNING · 희소 보상의 대가

설계는 쉬워지지만 학습이 극도로 어려워진다. 몇 분짜리 과제에서 끝에 1점 하나만 받으면, 수천 개 행동 중 어느 것이 좋았는지 알 수 없다. 이것이 credit assignment 문제이고, PART 2의 가치함수가 이 문제를 푸는 도구다.

정책 π (policy)

상태를 받아 행동을 내놓는 것. RL이 학습하려는 대상이 바로 이것이다.

π(a ∣ s)

이 표기가 중요하다. “s가 주어졌을 때 a의 확률분포”라는 뜻이다. 하나의 행동을 딱 내놓는 게 아니라 확률적이다.

종류표기뜻
결정론적 (deterministic)a = μ(s)같은 상태 → 항상 같은 행동
확률적 (stochastic)a ∼ π(a∣s)같은 상태 → 뽑을 때마다 다른 행동

확률적이어야 하는 이유는 탐색(exploration). 항상 같은 행동만 하면 더 나은 방법을 발견할 수 없다.

VLA는 π(a ∣ o, 언어 프롬프트)다. 언어가 조건에 추가된 정책일 뿐이다.

에피소드와 궤적

  • 에피소드 (episode): 시작부터 끝(성공/실패/시간초과)까지 한 번의 시도
  • 궤적 (trajectory) τ: 그 에피소드에서 일어난 일의 기록
τ = (s₀, a₀, r₀, s₁, a₁, r₁, …, sT)
  • 전이 (transition): 한 스텝 분량 (s, a, r, s′). 리플레이 버퍼에 저장되는 단위.
  • 롤아웃 (rollout): 정책을 실제로 돌려서 궤적을 만드는 행위

할인율 γ (gamma, discount factor)

0 < γ ≤ 1 사이의 수. 보통 0.99.

“미래의 보상은 현재의 보상보다 조금 덜 소중하다”는 뜻이다.

리턴 Gt = rt + γrt+1 + γ²rt+2 + γ³rt+3 + ···

이 리턴(return)이 RL이 최대화하려는 대상이다. “지금부터 끝까지 받을 보상의 할인 합”.

γ가 필요한 이유 세 가지:

  1. 수학적 안정성 — 무한히 계속되는 과제에서 합이 발산하지 않게
  2. 불확실성 반영 — 먼 미래는 예측이 불확실하므로 덜 신뢰
  3. 빠른 완수 유도 — 같은 보상이면 빨리 받는 게 유리 → 자연히 속도 최적화

TIP · γ와 “속도”의 연결

Levine 장면 8에서 RL 정책의 사이클 타임이 BC의 절반이었던 이유 중 하나가 γ다. 늦게 성공하면 γT로 할인되므로, 빠른 성공이 수학적으로 더 높은 리턴을 받는다. 아무도 “빨리 해”라고 말하지 않았는데 빨라진다.

마르코프 성질 (Markov property)

P(st+1 ∣ st, at) = P(st+1 ∣ s₀, a₀, …, st, at)

말로 하면: “다음에 무슨 일이 일어날지는 지금 상태만 알면 충분하다. 과거 이력은 필요 없다.”

마르코프 정책이란 지금 관측만 보고 행동을 정하는 정책이다. 같은 화면이면 항상 같은 행동 분포.

EXAMPLE · 왜 이게 RLDG의 핵심인가

Levine 장면 9의 “RL 데이터가 같은 개수의 사람 데모보다 낫다”는 발견은 마르코프 성질 때문이다.

사람은 마르코프가 아니다. 똑같아 보이는 화면에서 어떤 날은 왼쪽, 어떤 날은 오른쪽으로 돈다(그날의 기분, 앞선 이력, 딴생각). 그러면 데이터에 “같은 입력 → 다른 정답”이 섞인다.

BC는 이걸 평균 낸다. 왼쪽 30% / 오른쪽 70%를 평균하면 어느 쪽도 아닌 방향이 나오고 커넥터는 안 꽂힌다. 이것이 mode averaging 문제.

RL 정책은 정의상 상태의 함수라 이 모순이 구조적으로 없다. 그래서 RL 롤아웃이 더 깨끗한 교재가 된다.

PART 2

가치 — V, Q, A 세 글자

RL 논문에서 가장 많이 나오는 세 기호. 전부 “얼마나 좋은가”를 재는 것이고, 무엇에 대해 재는지만 다르다.

V(s) — 상태 가치 함수 (state value function)

V(s) = 𝔼[Gt ∣ st = s]

“이 상태에 있으면, 앞으로 총 얼마나 좋을까(리턴의 기대값)”

  • 포터필터가 잘 물린 상태 → V 높음
  • 커피를 쏟은 상태 → V 낮음

𝔼(기대값)가 붙은 게 중요하다. 평균이다. 한 번의 결과가 아니라 “이런 상태에서 보통 어떻게 되는가”.

Q(s,a) — 행동 가치 함수 (action value function)

Q(s,a) = 𝔼[Gt ∣ st = s, at = a]

“이 상태에서 이 행동을 하면, 앞으로 총 얼마나 좋을까”

V와의 차이는 행동을 지정했다는 것. 그래서 Q가 있으면 행동을 고를 수 있다.

a* = arg maxa Q(s,a)

이것이 EXPO의 argmax Q가 하는 일이다.

V와 Q의 관계:

V(s) = 𝔼a ∼ π[Q(s,a)]

즉 V는 Q를 정책에 대해 평균 낸 것. “이 상태의 가치 = 이 상태에서 내가 할 행동들의 평균 가치”.

A(s,a) — 어드밴티지 (advantage)

A(s,a) = Q(s,a) − V(s)

“이 행동이 평균보다 얼마나 나은가”

EXAMPLE · 왜 상대적으로 재야 하나

시험 점수 80점이 좋은가? 반 평균이 50점이면 훌륭하고, 95점이면 나쁘다. 기준선(baseline)을 빼야 의미가 생긴다.

로봇에서도 같다. 에스프레소를 거의 다 만든 상태에서는 아무 행동이나 해도 Q가 높다(어차피 곧 성공). 그 상태의 V가 이미 높으니까. A = Q − V로 빼주면 “이 행동이 진짜 기여한 몫”만 남는다.

A의 성질:

  • A > 0: 평균보다 좋은 행동 → 확률을 올려야 함
  • A < 0: 평균보다 나쁜 행동 → 확률을 내려야 함
  • 𝔼a ∼ π[A(s,a)] = 0 (정의상 평균은 0)

기술적으로 baseline을 빼면 분산이 줄어 학습이 안정된다. 이것이 policy gradient에서 A를 쓰는 이유(PART 8).

두 발표의 advantage 정의 읽기

Levine 장면 19 / π*0.6 (RECAP):

A(o,a) = rt:N + V(ot+N) − V(ot)

이걸 뜯어보면:

  • rt:N: t부터 N스텝 동안 받은 보상
  • V(ot+N): N스텝 후 상태의 가치
  • V(ot): 지금 상태의 가치

앞의 두 항 rt:N + V(ot+N)이 “N스텝 실제로 가본 뒤 추정한 Q”다. 거기서 V(ot)를 빼면 정확히 A = Q − V 형태. 이것을 N-step advantage라 부른다.

Finn 00:10:50: “advantage는 행동 전후 가치의 차이로 계산한다”

같은 것을 말로 표현한 것이다. 희소 보상이라 중간 r이 0이므로 A ≈ V(이후) − V(이전)로 단순화된다.

QUESTION · “가치가 단조 감소하는데 왜 advantage에 음수가 나오나”

자주 생기는 혼동이다. 한 에피소드 안에서 “끝까지 남은 시간” 라벨은 단조 감소한다. 하지만 V는 라벨을 외우는 게 아니라 상태를 보고 기댓값을 예측하는 함수다.

  • “포터필터 잘 물림” 상태 → 이 상태가 등장한 에피소드들의 평균 잔여 시간 20초
  • “포터필터 떨어뜨림” 상태 → 평균 잔여 시간 50초

떨어뜨리는 행동은 V가 높은 상태에서 낮은 상태로 이동시키므로 A < 0. 에피소드 내 라벨은 단조지만 상태의 함수로서의 V는 단조가 아니다.

따라서 가치함수는 실패 데이터도 학습해야 한다. 떨어뜨린 장면이 데이터에 없으면 그 상태의 가치를 알 수 없다.

PART 3

가치를 어떻게 배우나 — 몬테카를로 vs TD

V나 Q를 어떻게 학습할까. 두 가지 근본적으로 다른 방법이 있고, 두 발표가 서로 다른 쪽을 골랐다.

방법 1: 몬테카를로 (Monte Carlo, MC) — “끝까지 가보고 실제 결과로 배운다”

에피소드를 끝까지 돌린 뒤, 각 시점의 실제 리턴을 계산해서 그걸 정답으로 회귀한다.

에피소드:  s0 → s1 → s2 → ... → s40 (성공!)

라벨 만들기:
  s0 의 정답 = 40 (남은 스텝)
  s1 의 정답 = 39
  ...
  s39 의 정답 = 1

학습: V(s) 가 이 숫자를 맞히도록 회귀 (MSE 손실)

이것이 그냥 지도학습이다. 입력은 이미지, 정답은 숫자. 특별한 RL 기법이 하나도 없다.

장점단점
편향 없음 (실제 결과가 정답)분산 큼 (한 에피소드의 운에 좌우)
극도로 안정적에피소드가 끝나야 학습 가능
지도학습이라 대형 모델로 확장 쉬움데이터 효율이 낮음

SUCCESS · Finn 발표가 MC를 고른 이유

수십억 파라미터 VLM에 value head를 얹어 학습해야 하는데, 대형 모델에서 검증된 안정적 도구는 지도학습뿐이다. TD의 불안정성을 감당할 수 없다. 편향 없음과 안정성을 얻고 데이터 효율을 포기한 것.

방법 2: TD 학습 (Temporal Difference) — “다음 상태의 추정치를 빌려 쓴다”

끝까지 갈 필요 없이, 한 스텝만 가보고 나머지는 자기 자신의 예측으로 때운다.

V(s) ← r + γV(s′)

말로 하면: “이 상태의 가치 = 지금 받은 보상 + 다음 상태의 가치(내 예측)”.

이것을 벨만 방정식(Bellman equation)이라 하고, 이 갱신을 벨만 백업(Bellman backup)이라 한다.

Q 버전(Q-learning):

Q(s,a) ← r + γ maxa′ Q(s′,a′)

TD 오차(TD error): δ = r + γV(s′) − V(s) — 예측과 실제의 차이. 이 값이 곧 advantage의 1-스텝 추정이기도 하다.

장점단점
데이터 효율 높음편향 있음 (내 예측을 정답으로 씀)
에피소드 안 끝나도 온라인 학습불안정 — 오류가 자기 강화됨

부트스트랩 (bootstrapping) — TD의 축복이자 저주

TD가 “자기 예측을 정답으로 쓰는 것”을 부트스트랩이라 한다. 이게 데이터 효율의 원천이자 모든 불안정성의 원천이다.

critic이 본 적 없는 행동 a* 의 Q값을 과대평가
  → actor가 "a* 가 최고네" 하고 그쪽으로 이동
  → 과대평가된 값이 벨만 백업으로 이전 상태에 전파
  → 전체 Q함수가 부풀어 오름 → 발산

자기 강화 루프다. 이것이 offline RL의 핵심 난점이고, RLPD가 LayerNorm과 critic 앙상블로 막으려 한 것이다. (상세: Sergey 노트 심화 해설 ② Q2)

중간 지점: N-step과 GAE

경사하강 (gradient descent) — “학습”이 실제로 무엇인가

RL 특유의 개념은 아니지만, EXPO의 “Q함수 뒤처짐”을 이해하려면 필요하다.

기본

신경망은 수백만~수십억 개의 파라미터 θ(가중치)를 가진 함수다. 학습이란 이 숫자들을 조금씩 바꿔 손실을 줄이는 것.

θ ← θ − α∇θL(θ)
  • L(θ): 손실함수 — 지금 얼마나 틀렸는지
  • ∇θL: 기울기(gradient) — 각 파라미터를 어느 방향으로 바꾸면 손실이 커지는지
  • α: 학습률(learning rate) — 한 번에 얼마나 움직일지. 보통 10−4 정도
  • 마이너스 부호: 손실이 줄어드는 쪽으로 가려고

EXAMPLE · 비유 — 안개 속 하산

산에서 안개 때문에 앞이 안 보인다. 발밑의 기울기만 느낄 수 있다.

전략: 가장 급하게 내려가는 방향으로 한 걸음씩 반복.

  • 기울기 = 발밑 경사
  • 학습률 = 한 걸음의 크기
  • 걸음이 너무 크면 계곡을 뛰어넘고, 너무 작으면 평생 못 내려간다

핵심: 경사하강은 느리다

한 번의 갱신으로 정답에 도달하지 않는다. 조금씩 수천~수만 번 반복해야 수렴한다.

IMPORTANT · 이것이 EXPO “뒤처짐”의 정체

Finn 00:22:00에서 edit policy가 Q를 못 따라가는 이유가 이것이다.

시각 t:      Q_t 를 최대화하도록 π_edit 경사하강 시작
시각 t+50:   π_edit 가 겨우 Q_t 를 따라잡음
             그런데 Q 는 이미 Q_{t+50} 으로 바뀜   ← 영원히 한 발 늦음

온라인 RL에서는 목표(Q)가 계속 움직인다. 경사하강은 움직이는 목표를 느리게 쫓아가는 도구다.

EXPO의 해법 argmax Q는 경사하강이 아니라 탐색(search)이다. 학습 스텝이 0회이므로 최신 Q를 즉시 쓸 수 있다. 두 개의 시간 척도를 겹친 것:

  • π_edit 학습 = 느린 개선 (경사하강, 수백 스텝)
  • argmax Q = 즉석 보정 (탐색, 0 스텝)

관련 용어

  • 역전파 (backpropagation): 기울기를 출력에서 입력 방향으로 연쇄법칙으로 계산하는 알고리즘
  • 배치 (batch): 한 번의 갱신에 쓰는 데이터 묶음. 보통 256개
  • 에폭 (epoch): 데이터셋 전체를 한 바퀴
  • UTD (Update-To-Data) 비율: 환경 스텝 1회당 경사하강 몇 번? 보통 SAC는 1, RLPD는 20. 실세계에서 비싼 건 로봇 시간이고 GPU는 싸므로 같은 경험을 20배 짜낸다. 이것이 “1~2시간 학습”의 정체.
  • 긴 체인을 통한 역전파의 문제: 디퓨전 정책은 denoising을 수십~수백 번 반복하는데, 그 전체를 통과해 기울기를 보내면 기울기가 소실/폭발한다. Finn 00:19:50의 “가치를 diffusion으로 직접 역전파 → 긴 denoising 체인 탓에 불안정”이 이것.

Q(s,a) = r + γ maxa′ Q(s′,a′)

이 식에는 정책이 등장하지 않는다. 그냥 전이 (s,a,r,s′) 하나만 있으면 검사할 수 있다. 그 전이를 누가 만들었는지는 상관없다.

정책의 형태 — 가우시안 vs 디퓨전

π(a∣s)를 신경망으로 어떻게 표현할까. 이 선택이 EXPO 전체의 이유다.

가우시안 정책 (Gaussian policy)

신경망이 행동을 직접 출력하지 않고, 정규분포의 평균과 표준편차를 출력한다.

π(a ∣ s) = 𝒩(μθ(s), σθ(s))
상태 s → [신경망] → μ = [0.3, -0.1, 0.5, ...]   (평균)
                    σ = [0.05, 0.05, 0.1, ...]  (표준편차)

행동 뽑기: a = μ + σ · ε ,   ε ~ N(0, 1)

왜 RL 알고리즘들이 가우시안을 전제하는가 — 세 가지가 다 쉽다.

  1. 확률 계산이 닫힌 형태로 가능 — log π(a∣s)를 공식으로 바로 계산. policy gradient에 필수.
  2. 재파라미터화 트릭 (reparameterization trick) — a = μ + σε로 쓰면 샘플링을 통과해 미분할 수 있다. SAC/TD3가 actor를 학습하는 방식.
  3. 엔트로피 계산 가능 — SAC의 엔트로피 항을 공식으로 구할 수 있다.

가우시안의 치명적 한계: 단봉(unimodal)

정규분포는 봉우리가 하나다. “왼쪽으로 돌기”와 “오른쪽으로 돌기” 둘 다 정답인 상황에서 가우시안은 둘 중 하나를 고르거나 둘의 평균(= 직진, 오답)을 낸다.

이것이 PART 1에서 본 mode averaging이고, 사람 데모를 BC할 때 커넥터가 안 꽂히는 이유다.

디퓨전 정책 (diffusion policy) / 플로우 매칭 (flow matching)

노이즈에서 시작해 여러 번의 denoising 스텝을 거쳐 행동을 만든다.

a_K ~ N(0,1)  (순수 노이즈)
  → denoise → a_{K-1}
  → denoise → a_{K-2}
  → ...
  → denoise → a_0  (최종 행동)

이미지 생성(Stable Diffusion)과 같은 원리를 행동에 쓴 것.

장점단점
멀티모달 분포 표현 가능 (봉우리 여러 개)log π(a∣s) 계산이 불가능/비쌈
복잡한 행동 분포를 정확히 모델링미분이 긴 체인을 통과 → 불안정
사람 데모의 다양성을 죽이지 않음샘플링에 forward pass 수십~수백 회

현대 VLA는 거의 다 디퓨전/플로우다. π₀, π₀.₅, π*0.6 모두. 표현력이 필요하니까.

그래서 디퓨전에 RL을 어떻게 걸까 — Finn 00:19:50의 세 갈래

기존 시도방법문제
① 가치를 직접 역전파denoising 체인 전체를 통과해 미분불안정 (PART 4의 긴 체인 문제)
② 여러 액션 뽑아 argmax Q후보 n개 중 최선 선택정책 자체가 개선 안 됨 — 제안 분포가 영원히 그대로
③ denoising을 가치로 유도매 스텝을 Q 기울기로 밀기정책 자체가 개선 안 됨

②③의 공통 문제가 중요하다. 정책이 학습되지 않으므로, base 정책이 애초에 못 만드는 행동은 n을 아무리 키워도 나오지 않는다.

EXPO의 해법 — 역할 분담

πbase: 디퓨전 (표현력)   +   πedit: 가우시안 (가치 최대화)
π_edit(ã | s, a)   ← 상태 s와 base 액션 a를 받아 "수정된 액션" ã 를 출력
  • π_base는 지도학습(imitation loss)만 받으므로 절대 무너지지 않는다
  • π_edit는 가우시안이므로 SAC/TD3의 검증된 off-policy 목적함수를 그대로 쓸 수 있다
  • 그리고 argmax Q가 원본과 수정본을 함께 심사하므로, edit이 망가져도 base가 안전망

표현력은 base가, 가치 최대화는 edit이 — 각자 잘하는 도구를 쓴 것이다. 이 분업이 성립하는 이유가 결국 “가우시안은 RL하기 쉽고 디퓨전은 표현력이 좋다”는 PART 6의 대비다.

액션 청킹 (action chunking)

한 스텝의 행동 하나를 내놓는 대신, 앞으로 H스텝 분량의 행동 묶음을 한 번에 출력한다.

π(at:t+H ∣ ot)
  • 왜 필요한가: 고주파 제어에서 매 스텝 추론하면 지연이 크고, 행동이 시간적으로 일관되지 않아 떨린다
  • Levine 장면 14 어블레이션: “w/o Chunk → 개선 실패”
  • Finn 00:25:00: EXPO-FT = EXPO + action chunking + human-in-the-loop

RL 관점에서는 행동 공간이 ℝ⁸에서 ℝ8×H로 커지는 것이라 원래는 불리한데, 실전에서는 압도적으로 이득이다. 로봇 RL의 필수 부품으로 자리잡았다.

PART 7

Actor-Critic 계열 — SAC와 TD3

off-policy RL의 표준 골격. Levine 발표의 RLPD가 이 계열이고, EXPO의 edit policy도 여기에 얹힌다.

기본 구조

부품역할비유
Actor π(a∣s)상태를 보고 행동을 낸다실제로 손을 움직이는 선수
Critic Q(s,a)그 행동이 얼마나 좋을지 채점옆에서 채점하는 코치

학습 루프:

1. Critic 학습: 벨만 백업으로 Q 를 정확하게 만든다 (TD 학습)
      target = r + γ Q(s', π(s'))
2. Actor 학습: Q 를 최대화하는 방향으로 정책을 민다
      maximize  Q(s, π(s))
3. 반복

왜 둘이 필요한가: Critic 없이는 “이 행동이 좋았나”를 알 수 없고, Actor 없이는 연속 행동 공간에서 argmaxa Q를 계산할 수 없다(무한히 많은 행동을 다 시도할 수 없으므로). Actor가 그 argmax를 근사하는 신경망 역할을 한다.

TIP · EXPO를 다시 보기

EXPO의 argmax Q는 이 근사를 샘플링으로 직접 하는 것이다. Actor(=edit policy)의 출력을 믿는 대신, 후보를 여러 개 뽑아 진짜 argmax에 가깝게 계산한다. Actor는 “제안 분포를 좋은 쪽으로 옮기는” 보조 역할로 격하된다.

계보: DDPG → TD3 → SAC

DDPG (Deep Deterministic Policy Gradient)

결정론적 actor + Q critic. 최초의 실용적 연속 행동 off-policy 알고리즘이지만 Q값 과대평가로 자주 발산한다.

TD3 (Twin Delayed DDPG) — DDPG의 세 가지 수정

트릭내용목적
Twin criticCritic 2개 학습, 타깃에 min 사용과대평가 억제
Delayed policy updateCritic 2번당 Actor 1번 갱신Critic이 안정된 뒤 Actor가 움직이게
Target policy smoothing타깃 계산 시 행동에 노이즈 추가Q함수가 뾰족해지는 것 방지

min(Q1, Q2)가 왜 과대평가를 막는가: 두 critic이 독립적으로 학습되면 각자 다른 곳에서 오차를 낸다. 둘 중 작은 값을 쓰면 “한쪽이 과대평가해도 다른 쪽이 견제”한다. 낙관적 오차만 골라 억제하는 셈.

SAC (Soft Actor-Critic) — 현재 로봇 실세계 RL의 사실상 표준

TD3의 twin critic을 가져오고, 확률적 가우시안 actor + 엔트로피 최대화를 추가한다.

J(π) = 𝔼[Σt rt + αℋ(π(·∣st))]

엔트로피 항의 의미: “보상도 높이고, 동시에 최대한 다양하게 행동해라.”

  • 정책이 너무 빨리 하나의 행동으로 굳는 것을 막는다 → 탐색 유지
  • 여러 좋은 해법이 있으면 다 유지한다 → 강건성
  • α(온도)로 강도 조절, 보통 자동 조정

이것을 maximum entropy RL이라 한다. Levine 그룹의 대표 기여이고, 로봇에서 SAC가 기본값이 된 이유다.

RLPD — SAC에 얹은 다섯 개의 설계 선택

Levine 장면 6의 알고리즘. 새 알고리즘이라기보다 SAC를 실세계에서 작동시키는 레시피.

재료내용
① Symmetric sampling배치 256개 중 항상 절반은 사람 데모에서. 데모가 희석되지 않게
② Critic에 LayerNorm어블레이션에서 가장 중요. Q값이 무한히 커지는 것을 구조적으로 차단
③ Critic 앙상블 + 랜덤 min10개 학습, 타깃 계산 시 무작위 2개의 min (REDQ)
④ 높은 UTD (=20)로봇 스텝 1회당 경사하강 20회. 샘플효율의 직접적 원천
⑤ SAC 엔트로피 유지탐색 유지

②③④는 세트다. UTD를 올리면 적은 데이터에 과적합하므로 ②③의 안정화가 반드시 필요하다.

상세 해설은 Sergey 노트 심화 해설 ② Q2에 있다.

PART 8

Policy Gradient 계열 — REINFORCE와 PPO

on-policy 쪽 계보. 두 발표에서 모두 “졌다”고 보고된 쪽이지만, 왜 졌는지 알려면 무엇인지 알아야 한다.

핵심 아이디어

정책의 파라미터를 리턴이 커지는 방향으로 직접 민다.

∇θJ(θ) = 𝔼[∇θ log πθ(a ∣ s) · A(s,a)]

이 식이 policy gradient theorem이다. 무섭게 생겼지만 뜻은 단순하다.

“좋았던 행동(A>0)의 확률은 올리고, 나빴던 행동(A<0)의 확률은 내려라.”
“그리고 좋았던 정도(A의 크기)에 비례해서 세게 밀어라.”

  • ∇θ log πθ(a∣s): “이 행동의 확률을 올리는 방향”
  • A(s,a): 그 방향으로 얼마나 밀지의 크기와 부호

A가 필요한 이유가 여기서 명확해진다. 만약 A 대신 그냥 리턴 G를 쓰면, 모든 보상이 양수인 문제에서는 모든 행동의 확률을 다 올리려 한다. baseline V를 빼서 “평균보다 나은가”로 바꿔야 방향이 생긴다.

REINFORCE

가장 단순한 policy gradient. MC로 G를 구해 위 식을 그대로 쓴다. 편향은 없지만 분산이 극도로 커서 실용적이지 않다.

Trust region — “한 번에 너무 많이 바꾸지 마”

policy gradient의 근본 문제: 기울기는 현재 정책 근처에서만 유효하다. 크게 움직이면 추정이 무의미해지고 정책이 붕괴한다.

TRPO는 KL 발산으로 제약을 건다.

maxθ J(θ)   subject to   DKL(πθold ∥ πθ) < δ

정확하지만 계산이 무겁다(2차 미분 필요).

PPO (Proximal Policy Optimization)

TRPO의 제약을 clipping이라는 값싼 트릭으로 대체한 것. 현재 가장 널리 쓰이는 on-policy 알고리즘이고, LLM의 RLHF 표준이다.

LCLIP = 𝔼[min(ρtAt, clip(ρt, 1−ε, 1+ε)At)],   ρt = πθ(at∣st) / πθold(at∣st)
  • ρt: importance sampling 비율 — “새 정책이 이 행동을 옛 정책보다 얼마나 더 좋아하나”
  • clip으로 ρ를 [1−ε, 1+ε] (보통 ε=0.2)에 묶는다
  • 효과: 정책이 한 번에 20% 이상 바뀌면 기울기가 0이 되어 더 안 움직인다

왜 로봇에서 졌는가

PART 5에서 이미 답했지만 정리하면:

  1. on-policy라 데이터를 버린다 — 실세계에서 치명적
  2. 사람 데모/개입을 활용할 수 없다 — 두 발표의 핵심 자산을 못 씀
  3. 분산이 커서 대량 샘플이 필요 — 실세계에서 확보 불가
  4. 큰 모델에서 기울기 노이즈에 취약 — 수십억 파라미터 VLA에 policy gradient 노이즈를 직접 넣는 것은 위험

Finn 발표의 실험에서 PPO는 trust region을 매우 작게(η = 0.01) 잡아야 겨우 안정됐고, 그러면 개선 폭도 거의 없었다. 안정성과 개선이 상충한 것.

NOTE · LLM에서는 왜 잘 되나

텍스트 생성은 샘플이 거의 공짜라 on-policy의 낭비를 감당할 수 있다. 그리고 RLHF는 “이미 아는 것을 배치하는” 정렬 작업이라 큰 정책 변화가 필요 없다 — clip 제약이 오히려 알맞다.

알고리즘의 좋고 나쁨이 아니라 문제 설정의 차이다.

PART 9

Offline RL과 정책 추출 — 네 가지 방법의 대결

“가치함수가 있을 때, 그것으로 정책을 어떻게 개선하나” — 이 질문이 두 발표의 핵심 논쟁이다. 이 절이 두 영상을 잇는 가장 중요한 부분이다.

문제 설정

데이터셋 𝒟(좋은 것 + 나쁜 것 섞여 있음)와 학습된 A(s,a)가 있다. 정책을 어떻게 뽑아낼까?

이것을 정책 추출(policy extraction)이라 한다.

방법 1: Filtered BC / SFT — “좋은 것만 골라 모방”

maxθ 𝔼(s,a)∼𝒟, A(s,a)>0[log πθ(a∣s)]

성공한 데이터만 남기고 평범한 지도학습.

장점단점
극도로 단순, 안정적데이터 대부분을 버린다
사전학습과 같은 파이프라인나쁜 데이터의 방향 정보를 못 씀
에피소드 단위 필터링은 해상도 부족

WARNING · π*0.6 논문의 SFT 베이스라인 정의

“finetuning the base π*0.6 pre-trained checkpoint with demonstration data for the target task. We refer to this finetuning as ‘SFT’ because the advantage values are fixed to True for all demonstrations.”

즉 데모만 쓰고 advantage를 전부 True로 고정한 것. 발표의 모든 개선 수치가 이 베이스라인 대비다.

치명적 문제: 로봇이 실수했지만 사람이 개입해 완료한 에피소드는 “성공”이므로 통째로 포함되고, 로봇의 실수까지 advantage=True로 학습된다. 실수를 좋은 행동으로 가르치는 셈.

성공/실패는 에피소드의 속성인데 좋음/나쁨은 스텝의 속성이다. 이 해상도 불일치가 filtered BC의 근본 한계다.

방법 2: AWR (Advantage-Weighted Regression) — “좋은 정도로 가중치”

maxθ 𝔼(s,a)∼𝒟[exp(A(s,a)/β) · log πθ(a∣s)]

버리는 대신 가중치를 준다. 이론적으로는 KL 정규화 RL의 정확한 해다(PART 9의 수식 참조).

왜 실전에서 무너지는가: 가중치가 지수함수다.

배치 256개 중 상위 5~10개가 가중치를 거의 독점
→ 나머지 246개는 실질 가중치 ≈ 0
→ 유효 배치 크기가 10 근처로 붕괴
→ 그래디언트가 요동

β에 극도로 민감하고, 잘못 잡으면 학습이 안 된다. Levine 장면 17이 지적한 바로 그 문제.

방법 3: Advantage Conditioning — “라벨로 입력에 넣기” (π*0.6 / RECAP)

maxθ 𝔼(s,a)∼𝒟[log πθ(a ∣ s, 𝟙[A(s,a)>ε])]

손실함수를 건드리지 않는다. advantage를 이진화해서 정책의 입력 토큰으로 넣는다.

  • 학습 시: advantage는 사후적으로 계산된 측정값. good/bad 둘 다 등장. 나쁜 행동도 bad 라벨을 달고 학습됨.
  • 추론 시: advantage를 계산하지 않는다. 그냥 good을 박아 넣는다. 측정이 아니라 주문.

IMPORTANT · “결과인데 어떻게 입력이 되나”

advantage는 명백히 행동의 결과다. 트릭은 학습 때와 추론 때 성격이 다르다는 것.

학습 시추론 시
데이터이미 수집됨, 결과를 안다아직 행동 안 함
advantage계산한다 (채점)주문한다 (명령)
값good / bad 둘 다항상 good

비유: 답안지에 채점자가 나중에 정답/오답 도장을 찍는다. 도장은 결과다. 하지만 그 답안지 뭉치로 학습한 뒤에는 “‘정답’ 도장 찍힐 답을 써봐”라고 주문할 수 있다.

LLM에 “이 문장을 [긍정적] 톤으로 써줘”라고 하는 것과 완전히 같은 원리. 톤은 문장을 읽고 나서야 판정되는 속성이지만, (톤, 문장) 쌍으로 학습해두면 생성 조건이 된다.

같은 장면, 다른 조건 → 다른 행동이 되는 것이 핵심이다.

조건 토큰출력
good손목을 돌려 각도 맞춘 뒤 삽입
bad기울어진 채 밀어넣음 → 걸림

억제(suppression)가 아니라 분리(separation)다. good을 넣으면 애초에 다른 분포에서 뽑으므로 나쁜 행동은 후보에 오르지 않는다. 그래서 추론 비용이 원래 VLA와 동일하다.

이진화하는 이유: 연속값이면 테스트 때 “얼마나 좋은 값을 요구할까”라는 하이퍼파라미터가 생기고, 욕심내서 학습 분포 밖의 값을 넣으면 엉뚱한 행동이 나온다(Decision Transformer의 고질적 문제). 이진이면 그냥 good.

계보: Upside-Down RL(Schmidhuber 2019) → Decision Transformer(2021) → RvS(2022). “upside-down”이 최대화할 출력이던 보상을, 조건으로 삼을 입력 자리로 뒤집었다는 뜻.

π*0.6이 한 걸음 더 나간 지점: Decision Transformer는 실제 에피소드 수익(return-to-go)으로 조건화해서 “운 좋게 성공한 궤적”을 걸러내지 못한다. π*0.6은 학습된 가치함수의 차이를 쓰므로 V가 이미 확률적 요동을 평균 내준 신호를 쓴다.

방법 4: CFGRL — “guidance로 증폭” (Levine 장면 16~17)

Advantage conditioning의 확장. 조건화만 하지 말고 세기를 증폭한다.

π̂(a∣s) p(o∣s,a)w
  • w = 0: 조건 무시 (데이터 전체 분포)
  • w = 1: 그냥 조건화 — 방향은 맞지만 약함
  • w > 1: 좋은 데이터의 모드로 줌인

지수의 효과가 극적이다. 0.7 대 0.3은 2.3배지만, 5제곱하면 0.75 = 0.17 대 0.35 = 0.002로 70배가 된다. 작은 선호 차이를 큰 선호 차이로 증폭하는 손잡이가 w다.

디퓨전 이미지 생성의 CFG scale과 완전히 같은 것. 조건이 “텍스트 프롬프트”가 아니라 “이 행동은 잘된 것”이라는 점만 다르다.

가장 중요한 성질: 추론 시점 방법이다. 학습은 전체 데이터로 한 번만 하고, 보수적/공격적을 w로 실행 순간에 조절한다. 논문 제목의 Controllable이 이 뜻.

주의: w를 너무 키우면 다양성이 붕괴하고 데이터 밖(OOD)으로 밀려나 “이론상 최고지만 로봇이 부술 행동”이 나온다. 이미지 생성에서 CFG scale을 20까지 올리면 그림이 타는 것과 같은 현상.

critic은 타깃 계산에 Q(s′, π(s′))를 쓴다. 그런데 π(s′)가 데이터에 없던 행동을 제안하면?

  • 신경망은 그 지점을 아무렇게나 외삽한다
  • 보통 과대평가 쪽으로 간다 (max 연산이 낙관적 오차를 골라내므로)

모방학습 쪽 어휘

RL만으로는 로봇이 안 되므로, 모방학습 용어도 필수다.

BC (Behavior Cloning, 행동 복제)

maxθ 𝔼(o,a)∼𝒟demo[log πθ(a ∣ o)]

사람 데모를 지도학습으로 그대로 흉내내는 것. 가장 단순하고 가장 널리 쓰인다.

SFT (Supervised Fine-Tuning)

LLM에서 온 용어. 로봇 맥락에서는 BC와 사실상 같다. 사전학습된 모델을 대상 과제의 데모로 지도학습 파인튜닝하는 것.

용어 주의: π*0.6 논문의 “SFT”는 좀 더 특수하게 “advantage를 전부 True로 고정한 조건부 BC”를 뜻한다(PART 9).

Covariate shift와 compounding error — BC의 고질병

BC의 근본 문제. 학습 분포와 실행 분포가 다르다.

데모에는 "잘 되는 길"만 있다
  → 로봇이 조금 벗어난다 (작은 오차)
  → 그 상태는 데모에 없다 → 무엇을 할지 모른다
  → 더 크게 벗어난다
  → 완전히 낯선 상태 → 완전히 엉망

오차가 오차를 부른다. 이론적으로 BC의 오차는 호라이즌 T에 대해 O(εT²)로 쌓이고(Ross & Bagnell), DAgger 같은 교정 기법을 쓰면 O(εT)로 줄어든다.

이것이 “모방학습만으로는 40%에서 멈춘다”의 이론적 근거다.

DAgger (Dataset Aggregation)

covariate shift의 정면 해법.

반복:
  1. 현재 정책으로 롤아웃 (학습자가 실제 방문하는 상태를 만든다)
  2. 그 상태들에서 전문가에게 "여기선 뭘 해야 하나" 질의
  3. (방문 상태, 전문가 행동) 을 데이터셋에 추가
  4. 데이터셋 전체로 재학습

핵심: 학습자 자신이 방문하는 상태에 라벨을 붙인다. 전문가가 만든 상태가 아니라. 그래서 “내가 실제로 저지르는 실수의 교정법”만 효율적으로 배운다.

증류 (Distillation)

한 모델(교사)의 행동을 다른 모델(학생)에게 옮기는 것. 로봇에서는 교사 정책을 롤아웃해서 데이터를 만들고, 그 데이터로 학생을 BC하는 형태가 보통이다.

Levine 장면 9(RLDG)의 핵심 도구. 손기술은 스페셜리스트에게서, 일반화는 VLA의 사전학습에서 온다.

경제적으로 중요한 지점: 사람 데모는 데이터 1시간에 사람 1시간이 들지만, RL 정책은 밤새 혼자 돌려도 된다. 데이터 수집 비용이 인건비에서 전기요금으로 바뀐다.

탐색 (Exploration) — 로봇 RL의 진짜 병목

RL은 “해보고 배우는” 것인데, 애초에 성공을 한 번도 못 하면 배울 게 없다.

무작위로 팔을 흔들어서 USB가 꽂힐 확률은 사실상 0이다. 희소 보상에서 보상을 한 번도 못 받으면 critic이 배울 게 없고, critic이 없으면 actor도 방향을 못 잡는다 → 영원히 제자리.

Levine 발표 Q&A의 핵심 답: 파운데이션 모델을 행동 사전확률(prior)로 쓰라.

아기는 구멍에 물건을 넣을 때 구멍을 보고 그쪽으로 손을 뻗는다. 손을 무작위로 떨지 않는다.

자주 헷갈리는 것 정리

V vs Q vs A

V(s)     = 이 상태, 얼마나 좋아?                    (행동 미지정)
Q(s,a)   = 이 상태에서 이 행동, 얼마나 좋아?         (행동 지정)
A(s,a)   = Q - V = 이 행동이 평균보다 얼마나 나아?  (상대적)

기억법: V는 상태만, Q는 상태+행동, A는 그 차이.

MC vs TD

MC:  끝까지 가보고 → 실제 결과를 정답으로  → 느리지만 안정적
TD:  한 스텝 가보고 → 내 예측을 정답으로   → 빠르지만 불안정

기억법: MC는 결산, TD는 가결산.

on-policy vs off-policy vs offline

데이터 수집과거 데이터
on-policy현재 정책으로 계속버림
off-policy계속 수집재사용
offline안 함고정 데이터셋만

기억법: on = 지금 것만, off = 아무거나, offline = 새로 안 모음.

SFT vs BC vs Filtered BC

세 개가 거의 같은 것이고, 차이는 데이터를 어떻게 고르는가뿐이다.

BC            : 데모 전부 모방
Filtered BC   : advantage > 0 인 것만 모방
SFT (π*0.6)   : 데모만 + advantage 전부 True 로 고정

advantage conditioning vs AWR vs CFG

학습 시 advantage vs 추론 시 advantage

가장 헷갈리는 지점. 한 번 더 정리한다.

학습 시:  결과를 이미 안다 → 계산한다  → 측정값(채점)  → good/bad 둘 다
추론 시:  결과를 모른다    → 계산 안 함 → 주문(명령)    → 항상 good

결과를 입력 자리로 옮겨서 조건으로 만든 것. 인과를 뒤집은 게 아니라, 인과를 아는 데이터로 학습해두고 나중에 원하는 결과를 역으로 요구하는 구조.
