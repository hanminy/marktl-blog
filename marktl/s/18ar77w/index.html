02 · Architecture

연결된 시스템

Unity의 AGX plant를 중심으로 ROS2 명령·상태, 센서, TF, GridMap과 외부 planner가 이어진다. 각 계층의 인터페이스는 이미 구체적이다.

현재 공식 MPC 경로

paper-style global dig planner + speed-command tracking MPC

현재 굴착기 자세 + 목표 깊이 → apex_mpc_paper_planner.py → CasADi/IPOPT 3-phase 경로 최적화 → E85 theta↔AGX affine calibration → joint sequence → apex_mpc_controller.py → apex/excavator/command → Unity/AGX

현재 closed loop는 state feedback → tracking MPC → AGX plant다. LiDAR/GridMap은 주로 실행 후 관측·평가에 쓰이며, 실제 ground-profile 입력 연결은 다음 단계다.

04 · Paper Fidelity

구현된 것과
아직 아닌 것

Global planning은 실제 라이브 굴착에 연결됐다. 반면 현재 tracking 계층을 논문 등가 dynamics MPC라고 부르는 것은 정확하지 않다.

구현됨
  • 논문 §3.3 global planning 구조
  • Phase 1 접근, Phase 2 굴착 최적화, Phase 3 인양/이동
  • 제약 하 굴착 궤적 생성
  • E85 실측 calibration 기반 live joint sequence 변환
  • speed-command tracking MPC
미연결 또는 미구현
  • force, pump power, pump flow limit
  • 실린더 displacement 기반 동역학 MPC
  • momentum 기반 disturbance estimator
  • feedback linearization
  • DDP + augmented Lagrangian solver

현재 tracking layer의 정확한 표현은 paper-inspired constrained kinematic MPC다.

07 · Risk Register

성능보다 먼저
신뢰성을 설계한다

자동 테스트, 문서 정합성, Unity 운영 복구성과 실차 안전 계약이 주요 기술 부채다.

자동 테스트 부족

Unity Test Framework는 설치됐지만 프로젝트 자체 NUnit/UnityTest는 발견되지 않았다. APEXBatchTest도 객체 존재 확인 중심이며 물리 동작과 종료 코드를 충분히 검증하지 않는다.

현재 QA는 자동 suite보다 handoff 기반 실험 절차와 일회성 수치 로그에 의존한다.

08 · Roadmap

권장 진행 순서

저장소 안정화가 0순위다. 그 위에 live smoke, 실지형 재계획, 회귀시험과 dynamics MPC를 순서대로 쌓는다.

0

저장소 안정화

MCP 버전 결정 → NuGet 추적 범위 결정 → generated skills 정책 → crash dump 제거/ignore → 문서 분리 커밋 → Claude 15커밋 baseline 승격 → 원격 백업.

1

GridMap 기반 실지형 재계획

굴착 평면 cell 추출, robust clipping, 1~2차 surface fit, residual 기록, pass별 재계획과 GridMap 기반 pit 체적 산출.

2

캘리브레이션과 자동 회귀시험

bucket sweep 확대, residual 검증, planner acceptance test, outlier gate A/B, clean restart/rate check, 1-pass·3-pass 정량 regression과 명시적 batch exit code.

3

논문 등가 local dynamics MPC

HydraulicPlant, 힘·유량·펌프 제약, 외란 추정, local dynamics MPC와 swing ψ state 승격. ML-Agents, HUD, Recording, HIL/CAN은 이후 재개한다.

10 · Verdict

기능 확장보다
재현성 확보

APEX의 강점은 어려운 계층을 실제로 연결했다는 데 있다. 다음 성공 조건은 이 성과를 clean baseline과 반복 가능한 증거로 바꾸는 것이다.

강점

  • 좌표계·TF·센서·토양·GridMap·planner 통합을 실제 실행으로 해결
  • 실패 원인과 복구 절차가 handoff/guideline에 축적
  • Phase B global planner가 현재 환경에서도 실제 solve
  • AutoScoop과 MPC 모두 terrain 변형과 GridMap 관측까지 연결

약점

  • 실험이 자동 회귀시험과 clean baseline으로 굳어지지 않음
  • 최신 성과가 로컬 Claude 15커밋에만 존재
  • MCP/NuGet generated 변경으로 worktree 오염
  • force/power/flow 기반 dynamics MPC가 아님
  • 실차 안전 계층과 HIL/CAN 미착수
