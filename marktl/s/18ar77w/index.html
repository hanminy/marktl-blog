2.2 ROS2 명령과 상태 경로

명령 경로:

외부 planner/MPC
  → apex/excavator/command
  → ExcavatorCommandSubscriber

2.5 현재 MPC 경로

현재 공식 명칭은 다음이 정확하다.

paper-style global dig planner + speed-command tracking MPC

현재 굴착기 자세 + 목표 깊이
  → apex_mpc_paper_planner.py
  → CasADi/IPOPT 3-phase 경로 최적화
  → E85 theta↔AGX affine calibration
  → joint sequence
  → apex_mpc_controller.py
  → apex/excavator/command
  → Unity/AGX

apex_mpc_paper_dig_runner.py는 pass마다 현재 자세를 읽고 재계획·실행·평가하는 상위 오케스트레이터다.

현재 live closed loop는 다음과 같다.

state feedback → tracking MPC → AGX plant

LiDAR/GridMap은 현재 실행 후 지형 관측·평가에 주로 사용되고 있으며, 다음 단계에서 planner의 실제 ground-profile 입력으로 연결할 예정이다.

4. 논문 반영 수준

구현됐다고 말할 수 있는 범위

  • 논문 §3.3의 global planning 구조
  • Phase 1 접근, Phase 2 굴착 최적화, Phase 3 인양/이동
  • 제약 하 굴착 궤적 생성
  • E85 실측 calibration을 통한 live joint sequence 변환
  • speed-command tracking MPC

아직 아닌 것

논문 §3.4의 다음 항목은 vendored 코드로만 존재하거나 미연결 상태다.

  • force limit
  • pump power limit
  • pump flow limit
  • 실린더 displacement 기반 동역학 MPC
  • momentum 기반 disturbance estimator
  • feedback linearization
  • DDP + augmented Lagrangian solver
명칭상 주의 현재 구현을 paper-equivalent dynamics MPC라고 부르면 안 된다. 현재 tracking layer는 paper-inspired constrained kinematic MPC에 가깝다.

이 구분은 [[260504_APEX 논문 등가 MPC 설계 검토]]의 초기 판단에서 상당 부분 진전됐지만 여전히 유효하다. 당시에는 global planner 자체가 미구현이었고, 현재는 global planning 계층이 실제 라이브 굴착에 연결된 상태라는 점이 가장 큰 변화다.

7. 품질과 기술 부채

7.1 자동 테스트 부족

Unity Test Framework는 설치돼 있지만 프로젝트 자체 NUnit/UnityTest는 발견되지 않았다.

현재 테스트 자산:

  • 정적 LiDAR test component
  • Assets/Editor/APEXBatchTest.cs
  • 수동/스크립트 기반 E2E 평가
  • handoff에 기록된 일회성 수치 테스트

APEXBatchTest는 씬 객체 존재 여부를 확인하는 smoke 수준이다.

  • 실제 물리 동작을 충분히 검증하지 않음
  • 모든 component 실패를 종료 코드에 반영하지 않음
  • 정상 완료 시 명시적 EditorApplication.Exit(0) 없음

현재 품질 보증은 자동 test suite보다 handoff 기반 실험 절차와 수치 로그에 크게 의존한다.

9. 최종 판단

강점

  • 좌표계·TF·센서·토양·GridMap·planner의 어려운 통합 문제를 실제 실행으로 상당 부분 해결했다.
  • 실패 원인과 복구 절차가 handoff.md, guideline.md에 자세히 축적돼 있다.
  • Phase B global planner는 스텁이 아니라 현재 환경에서도 실제 solve된다.
  • AutoScoop과 MPC 모두 AGX terrain 변형 및 GridMap 관측까지 연결돼 있다.

약점

  • 성공한 실험이 자동 회귀시험과 clean baseline으로 굳어지지 않았다.
  • 최신 성과가 claude/r1 로컬 15커밋에만 존재한다.
  • 작업 트리가 대량의 MCP/NuGet generated 변경으로 오염돼 있다.
  • 실시간 제어는 아직 force/power/flow 기반 논문 등가 dynamics MPC가 아니다.
  • 실차 안전 계층과 HIL/CAN 구현이 미착수다.

권장 진행 순서

저장소 정리
  → 최신 baseline 통합·원격 백업
  → clean live smoke 재검증
  → GridMap surface fit 기반 pass별 재계획
  → 자동 회귀시험
  → HydraulicPlant 및 dynamics MPC

현재는 기능을 더 넓히기보다 이미 검증한 성과를 정리하고 재현 가능한 baseline으로 굳히는 것이 프로젝트 전체 성공 가능성을 가장 크게 높인다.
